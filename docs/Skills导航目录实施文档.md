本文只讲"怎么做"，不重复"为什么"。范围、领域、规则内容的最终解释权在需求文档。

状态：**尚未开始任何改造**。本文是实施基线，不是已完成的记录。

## 1. 目标产物

一条无常驻进程的生产线：

```
每周触发 → 发现 → 去重 → 领域预筛 → AI 评估（≤50/周）→ 唯一索引 → 生成静态页 → 发布 Pages
```

**不做**：不下载/镜像/安装/执行任何技能包；不建常驻服务、数据库、登录、管理后台；不修改上游仓库、上游域名及其 Vercel 项目。

发布地址：`https://justdoit712.github.io/skill/`（以 Pages 实际返回为准）。所有相对资源、数据请求、canonical、sitemap、robots 按 `/skill/` 子路径生成，不生成 CNAME。

## 3. 数据与配置契约

### 3.1 `config/sources.json`（每条来源）

`id`、`url`、`source_type`、`domain_ids`、`discovery_method`、`verification_status`，另存核验时间、具体技能路径、来源版本、许可状态（§4.3）。

初始来源按 §4.3 的表配置；金融与健康必须配独立社区入口，**没有合格条目的领域显示缺口，不伪造覆盖**。

### 3.2 评估输出（每次调用）

六维，每项 `pass` / `fail` / `unknown`，附链接或文件位置：

`scope_match`、`purpose_clarity`、`instruction_completeness`、`evidence_traceability`、`dependency_transparency`、`risk_review`

另含 `domain_checks`、`reason_codes`、`rules_version`、`source_fingerprint`（§5.2）。

判定：全部 `pass` + 领域检查通过 + 结构有效 → 推荐；有 `unknown` 或说明不完整 → 候选；命中硬性拒绝项 → 排除。网络/解析/模型错误**属于处理失败，不是质量判定**。

### 3.3 索引条目（`data/catalog.json`）

名称、原始链接、作者或团队；中文简述（一至两句）；主分类 + 标签 + 上游声明的平台/工具/依赖；来源类型、发现渠道、来源依据；候选/推荐状态与独立的待复核标记；评估理由与限制；首次发现、最近检查、内容变更时间或版本标识；上游移除/不可访问状态（§6）。

约束：不编造用途、平台兼容性和变更时间；**最近检查时间不得冒充技能更新时间**；上游未说明的不得推测为全平台兼容。

### 3.4 评估 ID

`技能稳定ID + 内容指纹 + 规则版本 + 模型配置版本`。不同目标版本的重评**同样消耗额度**（§7.3）。

## 5. 每周运行链路（单次顶层运行）

不靠机器人提交触发第二次 `push`——`GITHUB_TOKEN` 触发的 push 不会启动新 workflow（§7.2）。

| 步 | 动作 | 要点 |
|---|---|---|
| 1 | 检出与预检 | 完整检出目标分支（含 `src/ config/ data/ public/`）；校验配置、密钥存在性、写权限、数据结构；**未准备好不调用付费模型** |
| 2 | 发现与预筛 | 更新候选队列与上游指纹；读取本周已消耗额度；不把待处理条目直接推荐 |
| 3 | 预留额度 | 调用模型**之前**把名额预留写入 `data/state/` 并成功 commit/push；失败则停止付费调用 |
| 4 | 评估与生成 | 更新 `catalog.json`、`queue.json`、`state/`、`reports/`；由这些数据生成 `public/data/` 与报告页；模型失败也要记录，不抹除上次有效条目 |
| 5 | 验证与提交 | 提交范围仅 `data/catalog.json`、`data/queue.json`、`data/state/`、`data/reports/` 及生成的 `public/`；**禁止 `git add .`**；自动任务不改代码、规则、README、密钥 |
| 6 | 发布同一产物 | 从同一工作区上传已生成的 `public/`，携带数据提交 SHA 与索引摘要；不重新稀疏检出旧 `public/` |
| 7 | 部署验证 | 记录部署结果与 artifact 对应 SHA；部署失败只重试该产物，不重新评估技能 |

补充约束（§7.2）：读写与部署共用同一 concurrency group 且 `cancel-in-progress: false`；写数据用 `contents: write`，部署用 `pages: write` + `id-token: write`，其余最小读取；遇到用户同时 push 用非强制提交，冲突则停止后续付费调用并重新加载状态。

### 5.1 周额度（§7.3）

- 以 `Asia/Shanghai` 周一 00:00 起算，ISO 周标识（如 `2026-W38`）；定时、手动、重跑**共享账本**，不提供绕过输入。
- 每个名额最多 2 次尝试，调用前持久化尝试计数；失败/超时**仍占本周名额**；手动重跑不重置计数。
- 批处理异常或 runner 被终止**不释放已预留名额**。
- 网络请求与来源检查不占 AI 名额。
- `dry_run`：只验证配置与计划，不调用模型、不写账本、不提交、不部署。

## 6. 清理执行顺序（§8.8）

1. 记录 Git 状态与基线，核实所有待操作路径位于本仓库内。
2. 提取可复用代码、来源线索、必要署名许可，形成具体文件变更。
3. 删除旧产品、DSH 与无关采集入口（§8.2、§8.3）。
4. 新索引、页面与任务接通后，再移除被替代的旧文件与依赖（§8.4）。
5. 验证无旧入口、无活跃 DSH 条目、无失效导航。
6. 验证额度上限、失败保留旧数据、候选/推荐状态与发布链路。

**只处理本仓库已核实路径**；不删除工作区外资料、用户未跟踪的本地配置（`.idea/` 等）；保留 Git 历史，不重写历史；不使用通配符删除全部 Markdown。

| # | 验收项 | 怎么验 |

| 1 | 以新导航为唯一产品 | 仓库无旧助手/DSH/安装备份入口 |

| 4 | 候选/推荐分区，理由可追溯，变化后标记待复核 | 构造内容变化样本走一遍状态流转 |

| 8 | 每周同步、手动同步、发布、报告能连通 | 端到端跑一次 |
| 9 | 来源失败不清空目录，索引与网页一致 | 模拟来源 404 |
| 10 | 不下载完整技能包、不执行技能、不泄露密钥 | 代码审查 + 日志抽查 |
| 11 | 删除内容、复用代码、许可证、页面链接经过核对 | 清理前后对照 |

## 9. 红线

- 不下载、镜像、安装、启用、执行上游技能包。
- 密钥、认证头、含凭据的请求信息不进入日志、仓库、网页。
- 上游文本是不可信资料，不得作为更改筛选规则、读取密钥或执行命令的指令。
- 不编造用途、平台兼容性、变更时间；不伪造中文简介与评估结论。
- 来源失败保留上次有效数据，不做批量删除或虚假下架。
- 自动任务不改代码、规则、README 与密钥。
- 不擅自突破每周 50 的额度上限。
