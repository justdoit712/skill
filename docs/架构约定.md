# 架构约定

更新时间：2026-09-30

项目采用 Python 模块化单体、JSON 持久化与原生 ES 模块静态页面。本文维护长期约束；当前命令与限制见[运行说明](运行说明.md)。`audit/` 与 `evidence/` 是对应日期的历史记录，不代表当前代码或远端运行状态。

## 分层与依赖

| 层 | 职责 |
| --- | --- |
| `tools/` | 公开 CLI、参数分派与退出码 |
| `src/catalog/` | 目录发现、预筛、评估、条目更新、队列、预算与离线维护 |
| `src/finder/` | 独立需求规划、搜索、材料收集、证据核验、排序与查找报告 |
| `src/infra/` | HTTP、GitHub、模型传输、原子写入与文件锁原语 |
| `src/shared/` | 中性身份、材料快照、字段规范与请求用量事实 |

- CLI 调用业务包；业务代码不反向导入 CLI。
- catalog 与 finder 互不导入，包括函数内导入；finder 不读取目录排除、收藏、冷冻、池或配额策略。
- infra 不导入业务包；shared 不导入 catalog、finder 或 infra，不读取模型凭据或目录策略。
- 编排调用规则、存储与报告；纯规则不得反向调用编排或执行 I/O。store 不导入采集、同步或维护用例。
- 包初始化保持简单，避免集中重导出隐式加载整个流水线。依赖和循环由 `tests/test_architecture.py` 约束。

## 材料与外部接口

`infra/http.py` 保留超时、重试、读取上限、状态和截断事实；恰好达到上限且 EOF 的材料可用。GitHub 通信共用 infra 实现，查询策略由业务构造；模型传输不包含业务 Prompt。

`DocumentSnapshot` 保存 path、text、fingerprint、fetched_at、source_url 和可空 resolved_ref。评估和证据核验使用同一批快照；仓库相对路径不能逃出仓库。空白、HTML 和实际超限的材料不得送审。

`MaterialBundle` 的身份由排序后的路径与内容指纹集合生成，读取时间不参与；manifest 保存来源、版本和读取错误，不复制全文。HEAD/分支不代表固定提交，只有实际确认的固定 revision 才能声明版本一致。

finder 主材料上限 64 KiB、总材料上限 96 KiB、最多 2 个显式引用文件。catalog 当前仅评估主材料。新增集合身份不改写历史 skill_id 或 evaluation_id，不自动触发全量重评；两阶段恢复抓取必须校验预留指纹，变化材料不得绑定旧评估身份。

## 条目状态与存储

普通目录规则 `1.3.0` 使用 `catalog/quality.py` 纯函数核验核心功能引用及适用领域证据；`catalog/evaluation.py` 每个候选执行一轮 `assessment`（不含失败重试）。实际价值并入用途明确，可操作性并入说明完整；`verification_note` 只展示验证方法或缺口，不设独立三项质量门槛，也不再请求第二轮模型复核。`quality_review.enabled` 控制质量核验，定向查找不复用这套目录策略。

编排层通过 `on_request` 在每次实际调用前后落盘、计费和检查预算。响应已保存的 `pending_evaluation` 在材料指纹与规则版本一致时直接核验复用，不追加模型请求；不匹配时拒绝复用。结果不明的请求进入恢复流程，不能自动重复付费。完整调用事实保存在账本 `requests`；规则升级不自动重评候选池中已完成条目。

本地目录由 `catalog/parallel.py` 固定调度两个候选，`parallel_evaluation=false` 时退回串行。评估请求可并发，账本、预算、候选池和结果写入串行化；预算与目标判断须计入在途请求。停止后不再派发，等待已发请求返回并保存，再释放目录会话锁。Finder 使用独立调度器，默认串行，可通过 `--concurrency 2` 启用双并发。

`catalog/entry_state.py` 的 `update_entry(previous, candidate, event, context)` 是统一纯更新函数，不决定预算或重试，不访问网络或文件。本地和 Actions 对相同事件须生成相同条目。

- 同版本无有效新评估时保留旧描述与依据。
- 新评估明确返回 null/空数组时接受空值；仅旧格式缺字段且版本相同才兼容继承。
- 新版本未成功评估时保留最近有效评估快照并标记待复核；连续失败不能用空记录覆盖有效快照。
- 人工收藏由 `config/governance/favorites.json` 驱动，人工屏蔽由 `config/governance/overrides.json` 驱动，自动主题屏蔽由 `config/governance/filter-rules.json` 驱动，冷冻由 `config/governance/snoozed.json` 驱动。收藏、人工屏蔽与冷冻不触发额外模型评估。

主题配置版本为 `2.0.0`，根字段 `blocked_topics` 的每项只要求 `name`，可用 `description` 补充边界；内部判定 ID 由运行时派生，不要求用户填写。主题判定并入新技能首次正常 `assessment` 请求，以材料中的主要用途与主题含义为依据，覆盖同义表达，不依赖自由用途标签的精确匹配，也不在检索阶段按词拦截。此判定不增加独立模型调用，但会增加提示词和判定输出，且失去关键词早挡的评估成本节省。

本地和分阶段入口共用首次评估边界：已有收藏、推荐、候选以及已有成功评估记录的技能均不补查；新技能失败后的首次成功评估仍可执行主题判定。首次成功评估明确命中才覆盖为排除，并保存原结论、主题和依据供审计；`unknown`、缺失字段或无有效依据保留原结论，不额外请求模型。历史缓存直接复用，规则增删不改变旧判定。

目录采集与维护使用同一根目录的 catalog 会话锁，锁覆盖初始读取到写出。主索引与派生页面分别原子替换，不宣称多文件事务。完成评估记录携带恢复所需事实，页面可从主索引重建；账本读取与周切换写入分开。

finder 本地 report.json 是运行事实，Markdown 和公共快照是派生物。仅在统一收尾按发布条件生成白名单公共投影，并使用短锁；派生写失败须诊断且可离线恢复。恢复命令与旧记录限制见验收记录。

## 查找与报告契约

查找复制生效模型配置并强制单次传输，避免隐式重试掩盖用量。候选尝试数、成功评估数、实际请求数分别统计；请求前持久化开始事实，未发出与结果未知明确区分。有效响应缺 usage 时保留当前结果，再停止后续模型调用，不能将未知用量当零。

规划要求至少一个 required，不能把质量加分项隐式升级。评估必须严格覆盖固定准则 ID；校验字段类型、枚举、长度和整数行号，不把布尔值、浮点数或对象强制转换成合法证据。核验不修改输入，路径、行号与完整引文必须匹配；原文匹配不能证明语义蕴含。排序不以星数替代证据，不用备选凑短名单。

正常无匹配、部分覆盖、全部搜索/展开/材料失败、中断与未知用量应分别表达。查询、仓库和材料受限时公开覆盖不足，结果不能声称全网最优。

新报告声明 schema_version；前端兼容旧报告但缺失计数显示未知，未知 schema 明确报错。公开错误使用稳定 code，不泄露本机路径或连接诊断；模型文本转义，卡片链接限制为 HTTP(S)。

## 前端状态与同步边界

前端（`public/js/`）运行于 GitHub Pages 静态宿主，架构上严格恪守以下边界：
- **无后端长连接与无自动双向同步**：不引入实时协同或服务端推送，业务同步模型为“单页 LocalStorage 暂存 -> 手动导出变更包/JSON -> 仓库手工提交”。
- **单页生命周期闭环**：条目标记、清空、变更包导出在单页面内形成完整业务闭环。用户单页点击“清空”即彻底清除存储与内存状态。
- **杜绝过度设计**：不维护脆弱的跨标签页 `window.storage` 广播监听机制；多标签页并发同步/清空属于脱离业务事实的非目标场景。状态加载以单页面初始载入或用户显式刷新为准。

## 模型管理与智能体交互约定

- **模型队列分层**：`shared/model_config.py` 负责纯配置解析、参数合并和身份；`infra/model_config.py` 统一权威路径加载；`infra/model_pool.py` 负责跨进程状态事务和有界轮换。轮换对象独立注入，不能放进会被深拷贝的配置字典。
- **请求事务边界**：队列传输层每次只发一次请求；业务回调在请求前保存 started 和预算预留，在响应后保存实际用量、拒绝证据、实际模型及有效参数指纹。保存完成后才持久化耗尽并重选。文件锁不跨网络请求或业务回调持有。原子替换失败必须抛错，不能降级为直接覆盖文件。
- **状态与恢复**：两入口共用项目根下 `data/local/model-pool-state.json`，仅明确额度拒绝写入 `exhausted_models`；空正文最多尝试 2 次后单独写入 `cooldown_models`，本轮跳过并跨重启冷却 30 分钟。全池耗尽为 `models_exhausted`，可用模型全部冷却为 `models_cooling_down`，候选仍待处理；空响应用量未知时停止自动重试。输入不适配只对本次调用跳过，全部不适配为 `input_limit_mismatch`。非零用量与额度拒绝冲突时停止。换模型重置临时错误重试次数，任务账本累计不重置。
- **模型身份**：队列指纹保留列表顺序，用于配置审计；实际请求指纹包括所选模型和阶段有效参数；候选续跑主键不依赖队列成员。队列模式保留已完成事实，拒绝把缺少匹配模型指纹的跨任务缓存当作当前模型结果。

- **模型配置解耦**：公开厂商配置为 `config/models/<厂商>.json`，通过 `auth.key_ref` 引用被 Git 忽略的 `config/secrets.local.json`；环境变量优先。`tools/switch_model.py` 激活时写入不含明文 Key 的 `config/models/model.json`，并尝试移除同目录 `model.local.json` 覆盖。保留私有覆盖时，运行加载器仍优先读取它；旧平铺路径仅作兼容，完整优先级见运行说明第 6 节。
- **队列切换边界**：当前生效配置含 `models` 时，切换工具默认拒绝覆盖，显式 `--force` 才允许替换。厂商队列配置与运行时耗尽状态分开维护；修改厂商模板不会自动更新已激活的配置。
- **智能体交互与执行边界**：当用户提出“切换模型”时，AI 助手仅提供切换命令行供用户执行，严禁私自调用工具执行切换命令，严禁私自发起网络请求或脚本测试模型；别的情况用户会显式说明。

## 验证与测试资产治理

- **环境说明**：本项目仅在 Windows PowerShell 环境本地运行与开发，不部署亦不在 Linux 中运行。
- **分层测试规范**：
  - **日常核心冒烟测试**（优先运行；数量和耗时以实际输出为准）：
    ```powershell
    .\.venv\Scripts\python.exe tools/run_tests.py --smoke
    ```
  - **全量单元测试与回归**：
    ```powershell
    .\.venv\Scripts\python.exe tools/run_tests.py
    # 或标准 unittest:
    .\.venv\Scripts\python.exe -m unittest discover -s tests -q
    ```
  - **前端原生测试**：
    ```powershell
    npm test
    ```
    当前 `package.json` 仅提供 `test` 脚本；Python 测试使用上述解释器命令。若 Windows Node 无法展开测试目录，可使用：
    ```powershell
    $frontendTestFiles = @(Get-ChildItem -LiteralPath tests/frontend -Filter '*.test.mjs' | ForEach-Object { $_.FullName })
    node --test @frontendTestFiles
    ```
- **测试资产“用完即收”治理原则**：
  1. 测试套件严格收敛为 10~15 个高内聚领域模块（`test_architecture`, `test_catalog`, `test_finder` 等），禁止碎片化发散。
  2. 短期实施方案（`*-spec.md`）落地验证后，仅挑 1~2 项长期核心守门用例合入主测试，其余阶段性验收测试随实施文档一并归档清理，杜绝测试资产无序膨胀。
