# QCE 裁剪脚本实施方案

日期：2026-10-11  
状态：方案评审与实施约定；尚未编写脚本。

## 一、评审结论

原方案可行：用一个通用脚本接收时间区间或消息 ID，完成 QCE HTML 的裁剪、数据结构更新、校验和原地写入。之后每次操作只需传入参数，复用同一套执行代码。

需要补齐的主要是接口约定：

| 原描述中的问题 | 本方案的约定 |
| --- | --- |
| 混用了 `--drop`、`--drop-range`、`--drop-ranges` 等名称 | 统一为 `--drop`、`--keep`；重复参数表示多个区间 |
| 单段和多段采用不同输入格式，既有两个参数又有逗号分隔 | 每段始终传两个参数：开始、结束；不另设逗号格式 |
| 未说明 `--keep` 与 `--drop` 是否能同时使用 | 两者互斥；同一种参数可以重复 |
| 提到了 `--drop-ids`，但缺少具体调用和组合规则 | 接收一个或多个 ID，可独立使用，也可在区间裁剪后追加删除 |
| “稳定”缺少可核对的完成标准 | 用实际 QCE 文件适配和自动化测试确认，验收项见下文 |

批量处理多个区间的设计保留。不设固定耗时指标；验收重点是参数行为正确、文件结构正确、结果可重复。

## 二、实现范围

- 拟实现路径：`D:\Trade\scripts\trim_qce.py`。
- 使用 Python 3，优先仅使用标准库。
- 首版适配本地已确认的 QCE 分块内嵌 HTML：包含 `QCE_METADATA`、Manifest、Chunks 和消息 ID 索引桶。
- 一次调用处理一个 HTML；一次接收一个或多个区间及指定消息 ID。
- 脚本不识别大师、群名、观点或聊天相关性；它只执行调用者传入的选择条件。
- 配套 JSON 和资源目录不参与写入。
- 不支持的 HTML 结构应明确报错，不尝试猜测后写入。

## 三、命令行接口

```text
py scripts/trim_qce.py --html 文件路径 [选择参数] [--dry-run]
```

| 参数 | 输入 | 行为 |
| --- | --- | --- |
| `--html` | 一个 HTML 路径，必填 | 指定处理文件 |
| `--drop` | 开始 结束，可重复 | 删除任一区间内的消息 |
| `--keep` | 开始 结束，可重复 | 保留任一区间内的消息，删除其余消息 |
| `--drop-ids` | 一个或多个消息 ID，可重复 | 删除指定消息 |
| `--dry-run` | 无值 | 完整计算并校验结果，输出统计，不写入文件 |
| `--help` | 无值 | 显示参数说明和示例 |

### 参数组合

1. 至少提供 `--drop`、`--keep`、`--drop-ids` 中的一种。
2. `--drop` 和 `--keep` 不能同时使用。
3. 多个区间按并集处理；重叠区间不会重复计算消息。
4. `--drop-ids` 可以单独使用，或与 `--drop`／`--keep` 配合；最终结果再排除这些 ID。
5. 消息 ID 始终按字符串处理，支持原始数字字符串和 HTML 中的 `msg-` 前缀形式；重复 ID 合并。找不到的 ID 报错并停止写入。
6. 时间默认北京时间。支持 `YYYY-MM-DD` 和 `YYYY-MM-DD HH:MM[:SS]`；纯日期包含起止两天，具体时间包含起止时刻。开始晚于结束时报错。
7. 不带 `--dry-run` 时，校验通过后原地更新指定 HTML；结果无变化时不重写文件。

### 调用示例

以下 `39/xxx.html`、`40/xxx.html` 是占位路径，调用时替换为实际文件名。

```powershell
# 删除一段日期
py scripts/trim_qce.py --html "39/xxx.html" --drop 2026-09-23 2026-09-27

# 删除一个具体时段
py scripts/trim_qce.py --html "39/xxx.html" --drop "2026-09-21 14:00" "2026-09-21 16:30"

# 一次删除多个时段
py scripts/trim_qce.py --html "39/xxx.html" --drop "2026-09-21 14:00" "2026-09-21 16:30" --drop "2026-09-22 08:00" "2026-09-22 09:00"

# 保留两整天
py scripts/trim_qce.py --html "39/xxx.html" --keep 2026-09-21 2026-09-22

# 保留多个分离的时段
py scripts/trim_qce.py --html "39/xxx.html" --keep "2026-09-21 19:30" "2026-09-21 21:00" --keep "2026-09-22 19:30" "2026-09-22 21:00"

# 按 ID 删除（ID 仅作格式示例）
py scripts/trim_qce.py --html "39/xxx.html" --drop-ids "7687844057410014024" "msg-7687844057410014030"

# 保留日期后，再排除指定消息
py scripts/trim_qce.py --html "39/xxx.html" --keep 2026-09-21 2026-09-22 --drop-ids "7687844057410014024"

# 预览，不写入
py scripts/trim_qce.py --html "40/xxx.html" --keep 2026-10-04 2026-10-04 --dry-run
```

## 四、实现顺序

### 1. 参数解析

解析文件路径、区间和消息 ID，检查组合及输入是否合法，生成统一的消息选择条件。

### 2. QCE 数据解析

读取 HTML，静态解析内嵌数据，不执行聊天页面脚本。取得元数据、分块消息、Manifest 和消息 ID 索引，核对实际消息数与结构。

### 3. 内存裁剪

一次遍历完成所有区间和 ID 条件的判断。保留原有消息顺序及完整消息对象，不重写正文、不合并消息、不顺便去重。

### 4. 更新页面数据

- 更新消息分块及清单，移除空分块或生成页面支持的空结构。
- 同步总数、日期范围、发送者统计、分块计数及消息 ID 索引桶。
- 重建受影响的搜索索引；可选的搜索缓存也可按原查看器支持的方式失效，确保实际搜索仍基于保留内容。
- 保留图片、文件等附件引用。
- 引用目标被删除时，保留引用预览，取消失效跳转。
- 保留原页面样式与查看器，不重做阅读界面。

### 5. 校验及写入

先校验内存中的完整结果。`--dry-run` 到此输出统计并结束；实际执行时，在原目录生成短生命周期暂存文件，确认源文件没有被并发修改后原子替换，并清理暂存文件。

任何解析或校验失败均停止写入。成功返回退出码 `0`，失败返回非零退出码，并给出具体原因。

## 五、输出与验收

每次输出：文件路径、预览或执行模式、原有数量、保留数量、删除数量、保留日期分布、因目标被删除而取消的引用跳转数量。

首版自动化测试至少覆盖：

- 单区间、多区间和重叠区间的删除／保留。
- ID 单独删除、重复 ID、区间与 ID 组合。
- 日期简写、具体时刻、非法参数、不存在的 ID。
- 全部保留、全部删除、对同一区间重复执行。
- 中文、长 ID、附件、引用及跨分块消息。
- 预览、失败和并发修改时不覆盖源文件。
- 实际写入后的重新解析及索引一致性。

结果必须满足：原有数等于保留数加删除数；保留消息顺序、正文和附件不变；索引、统计与消息集合一致；不修改配套 JSON 或资源文件。

本地实际文件用于只读适配验证；写入测试使用临时测试样本。具备页面验证条件时，再检查打开、滚动、搜索和引用跳转；未完成的检查明确记录。
