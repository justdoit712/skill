# 模型队列自动轮换实施规范（Model Pool Auto-Rotation Spec）

> **版本**：v1.2.0<br>
> **日期**：2026-09-30<br>
> **状态**：已实施并完成离线验收；完整回归保留 1 项已确认的原有失败，详见 [验收记录](2026-09-30-model-pool-auto-rotation-acceptance.md)。<br>
> **执行环境**：Windows PowerShell，项目解释器 `.\.venv\Scripts\python.exe`。  
> **适用范围**：普通查找 `tools/run_local.py` 与定向查找 `tools/find_skill.py`，共用百炼兼容接口下的模型队列和耗尽状态。

## 1. 目标与范围

用户只维护 `config/models/model.local.json` 中模型的先后顺序，定期删除耗尽模型、添加新模型。程序收到明确的免费额度耗尽响应后，持久化记录并换下一个模型，继续当前未完成请求。重启跳过已耗尽模型；不考虑额度恢复，不设状态过期时间，不定期探测。

用户在阿里云侧为相关模型开启“用完即停”。程序不根据本地估算的 1M Token 判断额度，不修改云端设置，也不保证识别所有未知网关错误。只有明确耗尽证据才标记耗尽并切换；请求发送前发现模型输入上限不足时，允许仅针对本次逻辑调用跳过该模型。

第一版限定为**同一接口、同一凭据配置下，满足任务能力要求的文本模型**。不自动发现模型，不自动删除或改写配置，不扩展为跨厂商、跨协议或多账户调度。

普通查找和定向查找：

- 共用配置解析、错误分类、轮换器实现和项目内耗尽状态文件。
- 各自维护任务预算、候选进度与报告，不共享任务计数。
- 支持同时在不同进程运行：一方标记耗尽后，另一方在下一次选取模型时读取到该状态；已经发出的请求正常收尾。
- 定向查找的澄清、规划、候选评估、反思等所有模型调用都必须接入，不能只改评估阶段。

## 2. 配置契约

### 2.1 配置示例

以下模型 ID 是占位符，实施时沿用用户实际填写的可用模型，不自动启用示例名单。

```json
{
  "model_config_version": "1.0.0",
  "provider": "dashscope",
  "endpoint": "https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions",
  "auth": {
    "api_key_env": "LLM_API_KEY",
    "api_key": ""
  },
  "models": [
    "<模型 A 的实际 ID>",
    {
      "model": "<模型 B 的实际 ID>",
      "request": {
        "timeout_seconds": 300
      },
      "limits": {
        "max_output_tokens": 4000
      }
    }
  ],
  "request": {
    "timeout_seconds": 600,
    "max_attempts": 2,
    "temperature": 0,
    "response_format": "json_object"
  },
  "limits": {
    "max_input_bytes": 262144,
    "max_output_tokens": 8000,
    "max_calls_per_week": 50,
    "max_total_tokens_per_run": 100000000
  }
}
```

这不是完整替换模板；现有其他任务配置仍应保留。凭据解析保持环境变量优先、本地私密配置次之。第一版不允许模型项覆盖 `endpoint`、`provider` 或 `auth`。

### 2.2 加载与校验

1. 两入口共用唯一加载器。优先使用 `config/models/model.local.json`；只在该文件不存在时兼容旧平铺路径。新旧两份同时存在时明确报冲突，不再按修改时间猜测。
2. 旧单模型格式只有顶层 `model`，保持原有行为，不启用模型池状态清理。
3. 顶层 `model` 与 `models` 按**字段是否存在**互斥，即使 `models` 为空也报错。队列必须为非空数组。
4. 模型 ID 必须为去除首尾空白后的非空字符串，拒绝重复项和未知项字段。对象项只允许 `model`、已支持的 `request`、`limits`、`capabilities` 字段。保留模型 ID 大小写。
5. `request`、`limits`、`capabilities` 按字段合并并深拷贝；不共享可变嵌套字典。标量显式覆盖，数组整体替换。完整 `response_format` 对象整体替换，不把两个 JSON Schema 递归拼接。
6. 模型级 `limits` 只允许覆盖单请求限制（如输出 Token、输入字节上限）；任务预算、周配额只能在任务/公共配置中定义，不能因换模型而变化。
7. 校验每个模型合并后的有效参数：类型、正数范围、格式能力与传输层支持字段。不支持的参数应报错，不能接受后静默丢弃；不能假定任何模型只改名称都能适配。
8. 配置在运行启动时生成不可变快照，运行中不重载模型列表或请求参数。只刷新共享耗尽状态。改变配置后需重启相关任务。
9. `--check` 和只读展示模式只解析、校验、读取状态，不创建状态/锁文件、不执行清理、不联网。

### 2.3 每次请求的有效参数

选择具体模型后，再根据业务阶段构造请求：

- `response_format` 必须由当前模型的能力与当前阶段契约重新解析，不能复用前一个模型的格式参数。
- Finder 现有澄清、规划、评估输出常量作为阶段上限；实际输出上限取阶段上限与该模型配置上限的较小值。禁止切换后又被硬编码的 10000 等数值覆盖。
- 每次选模后重新检查材料是否满足输入限制、重新计算预算预留；不静默截断材料。若模型输入上限不足，不发送请求、不预留预算、不增加物理请求数，仅在本次逻辑调用中跳过该模型，继续按配置顺序寻找能接收完整材料的模型；记录跳过原因，但不标记耗尽。下一次逻辑调用仍可选择该模型。
- 若尚有未耗尽模型，但它们都无法接收本次材料，以输入限制不匹配受控停止并保留未完成任务，不报告 `ALL_MODELS_EXHAUSTED` / `models_exhausted`。单次选模扫描有界，不反复回到已跳过的模型。
- 轮换器作为独立运行对象注入各阶段，不放入会被 `deepcopy` 或 JSON 序列化的配置字典中。阶段复制配置不能创建独立游标。

## 3. 精准错误识别

### 3.1 白名单与错误元数据

首版自动轮换白名单仅包含已确认的百炼免费额度拒绝标识 `AllocationQuota.FreeTierOnly`。从完整可解析响应的 `error.code` / `error.type` 精确匹配，记录 `provider_error_code`；不从截断的 `error` 展示文本反推，不依赖消息中的 `quota`、`exhausted` 或 HTTP 403 单独判断。

`Arrearage` 等账户欠费错误不能当成某个模型独立耗尽。`OutOfQuota`、`QuotaExhausted`、`FreeTierExpired` 等未核实含义的名称不进入默认白名单。新增标识必须先核实服务商语义、作用范围及真实响应结构，并补充脱敏测试样例。

错误正文非 JSON、字段类型不合法、标识冲突或来源不匹配时，不猜测为耗尽。记录安全的诊断字段，不持久化凭据、完整请求或原始错误正文。

### 3.2 决策矩阵

| 结果 | 行为 | 标记耗尽 |
| --- | --- | --- |
| 明确匹配免费额度拒绝白名单 | 先结算并保存本次尝试，再记录耗尽，选择下一个模型 | 是 |
| 白名单额度拒绝同时携带明确有效的非零 usage | 先记录实际消耗并结算，随后停止并报告响应事实冲突，不自动重发 | 否 |
| 请求前发现当前模型输入上限不足 | 本次逻辑调用跳过该模型，继续寻找能接收完整材料的模型；全部不适配则受控停止 | 否 |
| 普通 401/403，账户欠费 | 报认证、权限或账户问题并停止，不轮换 | 否 |
| 模型不存在、请求参数不支持 | 报配置错误并停止，不轮换 | 否 |
| 408/429/指定 5xx、网络异常 | 保持入口既有重试及未知用量规则 | 否 |
| 截断、格式校验失败 | 保持原业务阶段的错误处理；规划失败不能当成“跳过技能” | 否 |
| 没有剩余可用模型 | 受控停止，保存未完成任务 | 否 |
| 状态写入失败或锁超时 | 停止新请求，明确报告存储/锁错误 | 否 |

响应事实冲突检查优先于自动轮换；精准耗尽识别优先于泛化 HTTP 分类，但不接受冲突或异常响应。不要把所有重试强行统一成“最多 2 次”：普通查找与 Finder 已有不同的编排规则。切换到新的实际请求模型时，临时错误重试计数重置，按该入口策略及新模型的有效配置重新获得完整重试额度；任务级预算与已发生的请求、用量累计不重置。

代码现状区别：`src/finder/run.py` 将一般 403 误归为耗尽，需要收紧；`src/catalog/failure_policy.py` 将 401/403 归为权限失败，需要在该分支之前处理明确耗尽/全池耗尽，保留普通 403 的权限语义。

内部统一使用 `QUOTA_EXHAUSTED`（单模型拒绝）、`ALL_MODELS_EXHAUSTED`（模型池无可用项）；两个入口的任务停止原因统一为 `models_exhausted`，不要混用多个拼写。

## 4. 共享状态与并发

### 4.1 状态文件

项目根目录下固定使用 `data/local/model-pool-state.json`，不受进程当前工作目录影响，由现有 `.gitignore` 排除。状态不存游标，按本次配置顺序减去耗尽集合选取模型。

```json
{
  "state_version": "1.0.0",
  "updated_at": "2026-09-29T15:20:00+08:00",
  "exhausted_models": {
    "<规范化 endpoint 与 model 的确定性哈希>": {
      "endpoint": "https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions",
      "model": "<实际模型 ID>",
      "exhausted_at": "2026-09-29T15:18:22+08:00",
      "error_code": "AllocationQuota.FreeTierOnly",
      "http_status": 403
    }
  }
}
```

endpoint 仅接受无 URL 用户凭据、无查询串、无片段的接口地址；规范化只处理协议/主机大小写和等价默认端口，保留路径语义。状态键使用结构化二元组序列化后的哈希，不使用有分隔符歧义的字符串拼接。绝不使用或落盘 API Key 作为键。

第一版共享状态假设两个入口使用同一账户配置；更换账户后继续跳过同端点同名耗尽模型，不自动清空状态。多账户隔离不在本次范围内。

### 4.2 锁与读改写

仅线程锁加原子替换不足以保护两个进程：它们可能各自读旧文件后覆盖对方记录。

必须同时具备：

1. 进程内锁保护本进程运行状态；跨进程文件锁保护共享文件的完整“读取—验证—合并/清理—原子写入”事务。
2. 可复用 `src/infra/files.py` 的 `file_lock`、`write_json_atomic`。锁文件建议使用 `data/local/model-pool-state.lock`，有界等待；现有锁是排他创建文件，进程被杀可能遗留锁，应明确提示，不能按时间擅自删除可能仍在使用的锁。
3. 每次请求选模时在锁内读取最新耗尽集合。另一进程刚写入的状态能被下一次选择观察到；选模后已在途的请求允许正常结束。
4. 标记耗尽时，按**失败请求携带的模型身份**合并，而不是对当前游标无条件加一。重复耗尽幂等，保留首次耗尽时间；总是重新从本任务列表选第一个未耗尽项。
5. 最后一个模型耗尽后返回明确的无可用项结果，不能数组越界；启动时已全部耗尽也要受控返回。
6. 不在共享锁内调用模型、等待重试、写任务账本或执行耗时业务回调；锁顺序固定，避免与 Finder 的预算条件锁形成死锁。
7. 存储失败时不继续请求下一个模型。内存状态不能代替持久化成功。

### 4.3 清理与损坏保护

- 首次不存在状态文件视为无耗尽记录；存在但损坏、缺字段、版本未知或记录身份不一致时明确报错，不覆盖。
- 正式运行启动时，仅清理当前 endpoint 范围内已从当前权威配置删除的模型，不删除其他 endpoint 的历史记录。
- 清理事务中重新读取权威配置并验证与本次启动快照一致；若启动期间文件变化则终止启动，要求重试。运行中的旧配置快照不执行清理。
- 旧进程迟到的耗尽响应在持久化前核对该模型是否仍在当前权威配置中；已删除则不重新插入磁盘记录，但仍在旧进程本地记为耗尽。该成员核对不代表热重载模型列表或请求参数。
- 配置或状态无法安全读取时中止相关操作，不用空列表替代并清空记录。
- 不自动恢复额度、不重新探测耗尽模型。删除后重新加入且对应记录已经清理，视为新加入项；尚未清理的同名项仍跳过。

## 5. 请求生命周期、用量与恢复

### 5.1 禁止只返回最后一次响应的隐藏重发

原方案 `while True -> call_model -> continue` 仅返回 B 的响应，会丢失 A 的尝试；现有 `UsageTotals` 又把未提供用量的额外尝试计为未知。必须把**每次物理 HTTP 尝试**接入现有账本，不能靠最终结果累加 `attempts` 掩盖过程。

统一轮换调度器接受阶段上下文和记账钩子，流程为：

1. 选择当前可用模型，生成有效请求和配置指纹。
2. 请求前调用预算/落盘钩子：预留预算，记录 `request_id`、关联的逻辑任务 ID、实际模型及 `started` 状态；保存成功后才发送。
3. 执行一次传输。队列模式不叠加底层隐藏重试；临时重试由既有编排策略决定，每次也经过相同钩子。
4. 响应后立即记录结果、实际 usage、错误码并结算预留；保存成功后再做切换决策。额度拒绝同时携带明确有效的非零 usage 时，记录实际消耗后停止并报告异常，不标记耗尽、不自动重发。
5. 若为无冲突的明确额度拒绝，持久化耗尽并重新选模；下一次请求重新预算和记账。输入上限不足的模型按第 2.3 节跳过。切换到新模型后重置临时错误重试计数。
6. 成功、普通错误或无可用模型时返回汇总，其中包含完整尝试记录及最终业务结果；上层不得再次重复累加这些已结算尝试。

同一逻辑调用中，一个模型一旦明确耗尽就不再请求该模型；其此前发生的临时错误重试仍完整记账。切换到新模型后临时错误重试计数重置，各模型的重试均受各自有效上限约束；不循环回到已耗尽或本次已跳过的模型，总请求量仍受有限队列、各模型重试上限与任务总预算约束。例如策略允许额外重试两次，A 已因网络错误重试一次后明确耗尽，切换到 B 时，B 仍可额外重试两次；A 的所有请求和消耗继续计入任务总账。

### 5.2 用量与次数的定义

- 每次真实 HTTP 请求都计入请求数；队列启动已耗尽且没有发送请求时请求数为零。
- 对能确认在推理前被拒绝的白名单错误，记录 `billing_state=rejected_before_inference`。服务端没有 usage 时保留原始 usage 缺失，以拒绝证据结算为无推理消耗，不伪造服务端返回的零 usage。
- 若返回明确有效 usage，保留并计入实际用量。白名单额度拒绝同时携带任一明确有效的非零 Token 用量时，先记账并结算，再停止并报告响应事实冲突，不标记耗尽、不自动重发。无 usage 或有效 usage 全为零的正常白名单拒绝可以轮换；usage 格式异常或其他事实冲突不属于正常拒绝，不能据此自动重发。其他缺少 usage 的请求继续遵守未知用量保护，绝不能借轮换丢掉超时的未知消耗。
- 更新 `src/shared/usage.py` 的实时累计、落盘摘要和 `recompute_usage_from_calls` / 对账逻辑，使拒绝请求不被错误计为未知，也不遗漏真实请求数。
- 区分逻辑评估次数、单模型临时错误重试次数与物理请求次数：纯额度拒绝不耗掉该候选的业务重试名额，也不递增通用失败计数。换模型时重置临时错误重试次数；既有候选业务尝试记录、任务级请求累计、Token 总量、周配额及任务预算上限均不重置。
- 每次切换重新按有效输出上限与实际 schema 预留预算，先释放明确被拒绝请求的预留。成功返回但用量缺失时仍按现有保护处理。

### 5.3 全池耗尽与恢复

全池耗尽是服务资源暂停，**不是候选自身失败**：

- 普通查找保留当前候选待处理状态和关联记录，不落成永久 `blocked`、`done` 或格式失败；补充模型后可以接着处理该候选，不需要人工解除阻断。
- Finder 保留阶段与材料检查点；澄清/规划等非候选阶段也能明确停止或按该阶段既有恢复规则重新进入，不能把未产出的计划当成功结果。
- 排入队列但未发送的请求标记为未发送并释放预留；已在途请求收尾并落账。全部耗尽后不再开始新的模型调用。
- `models_exhausted` 纳入两个入口的停止分类、优先级、标签、报告及恢复逻辑。存储错误、已有未知请求等阻断恢复的事实必须同时保留，不能被该停止原因掩盖。
- 启动时已经全部耗尽也生成明确结果，尽量在抓取/搜索前停止；不抛未捕获异常。
- 若在请求发出后结果未落盘前崩溃，保留现有未知结果保护，不自动重复可能已成功的调用。

普通查找沿用持久化候选池，重新启动即可；Finder 使用已有 `--resume`。本次不为普通查找新增 `--resume` 参数。

## 6. 模型身份、指纹与缓存

1. 每条物理请求存储实际模型、有效参数指纹、阶段、状态及切换原因；最终候选结果记录产出模型。报告顶层使用 `models_used` 等汇总信息，不把整次运行错误标成第一个模型。
2. 若后端返回不同模型标识，分别保存 requested model 与 returned model；耗尽状态以请求的配置身份为准，不用返回的别名替换队列 ID。
3. `build_config_fingerprint` 覆盖规范化模型队列及有效参数，**保留数组顺序**，只排序对象键。不纳入密钥、运行游标、耗尽时间或原始配置全文；使用允许字段构建脱敏指纹。
4. 仅修改报告指纹不够：现有 `catalog/evaluation.py::evaluation_id`、`catalog/queue.py::skill_evaluation_id` 及缓存复用还依赖 `model_config_version`。需统一模型身份生成与消费端，避免两套 ID 不一致。
5. 分开三类身份：队列指纹用于运行配置审计，实际模型配置指纹用于模型相关结果缓存，候选/材料/业务规则的稳定身份用于续跑关联。轮换过程中不能替换已创建账本的主键；最终模型身份作为记录事实附加保存。
6. 追加/删除模型导致队列指纹改变时，续跑记录一次配置变化。已有完成结果保留原模型归属，不自动重评；尚未完成的候选继续处理。新增模型不能导致整个任务的已完成结果被清空。
7. 使用明确期望模型的跨任务缓存时只匹配相应模型配置指纹；不同模型结果不得冒充。旧结果缺少新指纹时不猜测补齐，可保留为历史成果，但不升级为经过新模型验证的缓存。

### 8.2 必须覆盖的测试

| 分组 | 验收要求 |
| --- | --- |
| 基本轮换 | A 拒绝→B 成功；A/B 拒绝→C 成功；每次尝试和实际模型均可追溯 |
| 启动与结束 | 重启跳过 A；启动已全耗尽零请求；运行中全耗尽保存检查点，无越界/未捕获异常 |
| 配置严格性 | 空队列、双字段（含空 models）、重复 ID、非法类型、不支持参数、新旧文件冲突均阻断 |
| 合并与能力 | 深拷贝不污染其他项；schema 整体覆盖；A/B 不同格式能力；阶段输出上限不覆盖模型上限 |
| 非耗尽响应 | 普通 403、401、429、欠费、未知 quota 码、非 JSON、长错误正文不误轮换 |
| 多线程 | A 同时耗尽只记一次；迟到 A 响应不跳过 B；最后项同时耗尽不越界；在途成功仍落账 |
| 两进程 | 普通查找与 Finder 同时运行，状态更新不丢失，一方更新后另一方下一次选择跳过该模型 |
| 清理竞争 | 删除 A 后清理只作用于当前 endpoint；旧进程迟到错误不恢复已删除项；配置变化期间启动拒绝 |
| 存储故障 | 损坏 JSON、未知版本、写失败、锁超时、遗留锁都不继续发模型请求、不清空状态 |
| 用量 | A 明确拒绝+B 成功不触发伪未知用量；额度拒绝携带有效非零 usage 时先计入消耗再停止，不标记耗尽、不调用 B；缺失或全零 usage 的正常拒绝可轮换，异常 usage 不自动重发；真实尝试数完整；超时/缺 usage 仍受保护；复算与总账一致 |
| 输入限制 | A 耗尽、B 输入上限不足、C 可接收时直接请求 C；B 零请求、无预算预留、不标记耗尽；下一逻辑调用仍可选择 B；所有未耗尽模型均不适配时保留未完成任务并报告输入限制问题，不误报全池耗尽 |
| 预算与重试 | B 输出/schema 上限变化后重新预留；余额不足不发送；A 消耗部分临时错误重试次数后切换 B，B 获得完整重试额度；各模型重试有界且不循环；切换不重置任务预算、请求累计和候选业务计数 |
| 恢复 | 普通查找全耗尽不永久 blocked，追加模型后处理同一候选；Finder 澄清/规划/评估等阶段正确恢复 |
| 崩溃窗口 | 请求前落盘失败不发送；响应未落盘时按未知恢复；耗尽已落盘而任务未推进可安全恢复 |
| 指纹与缓存 | 队列重排改变指纹；密钥不进入指纹/日志；追加模型不重做完成候选；不同模型缓存不混用 |
| 原有行为 | 单模型兼容；无模型调用的纯离线任务不受状态损坏阻断；`--check` 不写文件 |

## 9. 日常操作

1. 在阿里云侧开启相关模型的“用完即停”。
2. 编辑 `config/models/model.local.json` 的 `models` 列表，删除用完的模型、追加新模型。配置更改后重启需要使用新队列的任务。
3. 普通查找沿用已有候选池继续运行：

```powershell
.\.venv\Scripts\python.exe tools/run_local.py
```

4. 定向查找恢复已有任务：

```powershell
.\.venv\Scripts\python.exe tools/find_skill.py --resume
```

有多个历史 Finder 任务时，按现有 CLI 支持的运行目录指定恢复目标。只有无冲突的明确额度拒绝才触发耗尽轮换重发；输入上限不足的模型在发送前跳过。临时错误按既有入口策略重试，切换到新模型后重置其重试次数；已有未知请求等恢复限制仍然适用。

5. 无须执行切换脚本。日志应显示“哪个模型已耗尽、下一次选择哪个模型、何时全部耗尽”，报告保存实际模型与请求事实。
