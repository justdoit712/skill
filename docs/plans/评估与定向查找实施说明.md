# 评估与定向查找实施说明

## 范围与执行顺序

本次落实两份方案中可以在当前机器离线实施的部分，依次完成：边界规则、Prompt 对齐、即时早停、引用重新定位、缺失字段处理、预算保护、候选队列检查点、分页补水、反思拓词、配置与报告。

旧机器运行记录缺失，不复用文档中的失败率作为已验证事实，不批量恢复旧候选。当前模型为本机配置选择的模型，不自动切换或联网校准。服务端输出能力未经核实，保留私有配置中的输出额度；不能承诺提高额度后不会截断。

## 普通目录评估

- 规则版本升为 `1.1.1`，防止将旧规则缓存当作新规则结果。
- 开启质量评估时，JSON 示例包含全部基础检查的 `citations` 与三个 `quality_checks` 子项；关闭时不要求这些字段。
- 缺失质量项填入 `unknown`、缺失理由和空引用，列入 `quality_audit.missing_quality_checks`。错误类型、未知质量项、非法核心检查仍是结构错误。
- 引用必须是原文的完整连续行。依次接受精确定位、起止行号偏差不超过 3 行且唯一的定位、全文中唯一的完整匹配。不接受片段相似匹配，也不凭模型解释跳过核验。
- 每项最多 3 条引用，每条最多 60 行。优先短引用；原模型输出不改写，实际行号及匹配方式保存到审计字段。
- 无法核实的通过项仍转为 `unknown`；独立复核和其他质量门槛保留。

## 定向查找边界

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `limit` | 5 | 经证据核验和排序后合格的短名单目标 |
| `max_rounds` | 3 | 首轮检索加最多两轮补水，空结果也计轮次 |
| `max_evaluations` | 200 | 累计候选评估尝试数，失败尝试也计入 |
| `max_tokens` | 20,000,000 | 累计用量停止阈值，包含澄清、规划、评估和反思 |

每次有效评估后立即检查目标，续跑开始也检查。用量未知优先停止；用量已知时，目标达成优先于同一次调用触及 Token 或次数上限。预算在下一次搜索、展开、抓取或模型调用前检查。实际用量只能在响应后确认，因此阈值是停止阈值，不能保证单次调用不会越过阈值。

所有定向查找模型请求禁用底层隐藏重试；GitHub 接口沿用最多三次的有界指数退避。连续模型失败阈值跨轮次与续跑保留。

## 补水与检查点

1. 先评估已保存候选，再展开已发现但未展开的仓库；存量耗尽后才开启新一轮搜索。
2. 每个关键词保存下一页及耗尽标记。每页 20 个仓库；不足一页表示耗尽。仓库使用规范化 `owner/repo` 去重，技能使用 `skill_id` 去重。
3. 仓库按查询交织，每批最多展开 20 个；保留其余仓库。展开保留返回树内的所有技能路径，公平调度不再静默丢弃第 11 个路径或第 81 个候选。模型尝试数仍由全局预算约束。
4. 先翻页；没有新仓库时反思。连续两轮有有效评估且全部为 `none` 时，下一轮优先反思。
5. 每个补水轮最多反思一次。模型只能返回 3–5 个短语，程序去重并拒绝搜索操作符、额外字段；原始需求、意图、评估准则保持不变。候选反馈最多五例，按不可信资料处理。
6. 报告保存轮次阶段、搜索页、仓库队列、候选队列、处理过的技能、连续失败数和反思结果。读取失败和格式失败也记录为本次运行已处理，不自动反复请求。
7. 已收到的模型响应与评估材料检查点保存到本地事实报告，可离线完成未落盘结果，不重复付费。发送后尚未确认的请求视作用量未知，续跑停止自动重试。
8. 旧报告缺少队列时，重新发现候选并跳过已有结果及已记录尝试；无法保证从缺失的旧游标精确接续。续跑不能更改原始需求。

## 状态与交付

| 原因 | 状态 | 退出码 |
| --- | --- | --- |
| `target_reached` | `completed` | 0 |
| `candidates_exhausted`（反思无新词） | `completed` | 0 |
| `round_limit` / `evaluation_limit` / `token_limit` | `stopped` | 2 |
| `usage_unknown` / `model_failures` | `stopped` | 2 |
| 搜索、展开、材料或反思失败 | `error` | 1 |
| `interrupted` | `interrupted` | 130 |

统一生成 `report.json`、`report.md` 和适用的公共快照。轮数耗尽时允许发布空结果，避免显示旧主题；完全基础设施失败且没有有效结果时保留旧快照。公共投影不包含内部队列、原始响应或材料检查点。

## 本地使用与验证

```powershell
# 正常运行（会发生联网搜索和模型调用，仅由用户主动执行）
.\.venv\Scripts\python.exe tools/find_skill.py "需求描述" --limit 5 --max-rounds 3 --max-evaluations 200

# 续跑继承累计次数与用量；需要时显式提高上限
.\.venv\Scripts\python.exe tools/find_skill.py --resume --max-rounds 4 --max-evaluations 300

# Python 回归
.\.venv\Scripts\python.exe -m unittest discover -s tests -q

# Windows Node 不接受测试目录参数时，显式展开文件
$frontendTestFiles = @(Get-ChildItem -LiteralPath tests/frontend -Filter '*.test.mjs' | ForEach-Object { $_.FullName })
node --test @frontendTestFiles
```

测试使用临时目录和模拟接口，不写生产数据。真实模型的输出完整率、推荐准确性、耗时与成本，需要后续小批量联网运行建立新基线；历史候选恢复需取回原始记录后另行筛选。
