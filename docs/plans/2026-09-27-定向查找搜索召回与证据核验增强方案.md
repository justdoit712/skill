# 定向查找搜索召回与证据核验增强方案

日期：2026-09-27  
状态：已完成实施（全量离线集成回归通过）；实现及验收详情参见 [2026-09-28 实施方案验收与对照记录](../audit/2026-09-28-实施方案验收与对照记录.md)。
范围：Skill Finder 的查询规划、搜索结果归因、证据定位和核验报告。

## 1. 目标与审查结论

在既有查询轮次、评估次数和 Token 预算内，增加符合需求的有效候选，减少因引用位置漂移产生的错误降级，同时保持对伪造、删改和跨文件拼接证据的拒绝。

| 原始提案 | 已核实的现状 | 建议调整 |
| --- | --- | --- |
| 为中文需求增加英文术语和同义词 | 规划 Prompt 已要求中英文关键词及同义表述，但解析后没有检查实际语言与术语覆盖 | 增加可解释的覆盖检查、有限术语补全及查询效果统计 |
| 使用 Token Overlap 容错核验 | 核验器已支持换行和连续空白标准化；仍要求完整引文存在于指定行区间 | 优先修复完整引文的定位漂移；重合度最多辅助找位置，不能直接决定通过 |
| 召回数量与质量提升两倍以上 | 尚无固定样本及同预算对照结果 | 作为待验证假设，不作为承诺或验收前已知事实 |

“查询更多”“搜到更多仓库”“找到更多有效 Skill”与“推荐更准确”是不同指标，需要分别衡量。

## 2. 当前实现与限制

### 2.1 查询规划

- `src/finder/plan.py` 的普通规划和交互规划均要求输出 3～8 条包含精准中英文关键词、同义表述的短语。
- 解析器限制最多 8 条，并进行空白规范化、部分搜索操作符清理和去重；当前并不强制解析结果达到 Prompt 所说的 3 条，也不保证中文需求实际包含英文技术表述。
- 初始查询去重与反思查询去重的规则不完全一致：后者已有大小写无关的去重。
- `build_reflection_prompt()` 已支持根据无匹配候选改进关键词，原始需求、意图及评估准则保持不变。
- `src/finder/refill.py` 已提供分页、反思补水、查询游标、去重、预算和恢复机制。增强查询应接入这些机制，不另建无界搜索循环。

### 2.2 搜索范围

`src/finder/search.py` 为短语固定附加 `"SKILL.md" in:readme`。从代码可以确认，这是一条额外的检索条件；其对有效仓库的覆盖影响需要通过样本验证，不能未经对照就归因于中文关键词。

系统目前以仓库检索后展开技能文件为主要路径。因此仓库结果数量不能直接当作 Skill 数量，合集中的重复发现也不能计为新增召回。

### 2.3 证据核验

实际文本核验位于 `src/finder/evidence.py`，`src/finder/evaluation.py` 调用核验器并调整匹配等级。

当前核验器会：

1. 要求文件存在于已读取材料集合中。
2. 拒绝布尔值、非整数和越界行号。
3. 拒绝空引文。
4. 将指定行区间及引文中的连续空白规范化，再检查完整引文是否为该区间的连续子串。
5. 在必需准则没有有效引用时，将其降为 `unknown`，重新计算匹配资格。

因此，当前并非完全不支持跨行，也不是要求引文必须等于整段完整行。现有机制不支持在行号错误时自动到附近寻找引文；标点或文字变化也可能导致失败。

历史运行说明和审计记录包含不同日期的状态，不能将旧文档中的问题直接认定为当前缺陷。后续应使用当前生产调用链验证每个问题。

## 3. 查询增强设计

### 3.1 输入边界

以用户原始需求及已确认的澄清结果为依据，提取核心技术概念、任务和明确约束。

- 用户未指定 Selenium、Playwright 等技术时，不因“网页爬取”自动将它们设为必需能力。
- 产品名、协议名和缩写保留原始形式，不机械翻译。
- 语言覆盖是按需求适用性检查，不要求每个需求都强行凑齐中英文数量。
- 扩展只影响搜索表述，不修改已确认的 `required`、`quality_signal` 和核心意图。

### 3.2 有限术语补全

维护小型、带版本的技术术语表，用于常见概念的稳定别名补全。示例：

| 概念 | 可用查询表述 | 约束 |
| --- | --- | --- |
| 网页爬取 | 网页爬取、web scraping、web crawler | 不默认增加登录、验证码或特定框架要求 |
| PDF 提取 | PDF 提取、PDF extraction、PDF text extraction | 不把文本提取自动等同于 OCR |
| 提示词优化 | 提示词优化、prompt optimization、prompt refinement | 不把优化自动等同于生成或评测 |

同义词和相关任务不是同一概念。术语表应记录适用范围，不能把相关词无限加入查询。

推荐流程：

1. 解析模型生成的查询计划。
2. 统一初始、交互及反思查询的空白规范化、大小写去重和操作符校验。
3. 检查是否覆盖核心概念、适用的技术表述及用户明确约束。
4. 对明确命中术语表且存在缺口的概念做本地补全；不为每个缺口自动增加一次模型请求。
5. 合并后仍受现有查询上限约束，保留直接需求和有差异的表述，去除低价值重复项。
6. 保存原始模型查询、最终查询、补全来源和术语表版本，便于解释及对照。

例如“网页爬取”可以形成“网页爬取”“web scraping”“web crawler”等独立查询，而不是把所有同义词堆成一条长查询。具体哪种表达有效，依赖后续结果统计。

### 3.3 查询调度与恢复

- 首轮、分页和反思共同使用已有仓库、技能去重集合。
- 对同一最终查询保持稳定身份与游标；术语表更新不能让续跑悄悄丢失已执行记录。
- 续跑默认使用已保存的最终查询计划及版本，不重新扩展整份计划。
- 保留现有失败页有界重试、限流等待和显式重试机制。
- 反思优先补充尚未覆盖的表达，不重复支付已经执行过的等价查询。
- 新增查询请求仍计入统计，并遵守轮次和停止条件；不能以“本地生成、不耗模型 Token”为理由无限增加 GitHub 请求。

### 3.4 搜索条件实验

先记录固定附加条件下的结果，再单独实验检索条件调整；不要同时改变术语扩展、分页规模和搜索条件，否则难以判断收益来源。

如未来尝试较宽的补充检索，应作为有界策略配置，单独记录来源，并继续通过仓库展开确认实际存在的 Skill。不能把一般爬虫库或普通 README 直接算作合格技能。

## 4. 证据定位容错设计

### 4.1 不采用重合度阈值直接放行

以下两句词语高度重合，但含义相反：

> 原文：This tool does **not** support authenticated crawling.  
> 模型引文：This tool does support authenticated crawling.

数字、版本号、文件路径、权限、否定词和代码运算符同样可能只差一个词或符号，却改变判断。简单分词重合度不能证明“模型没有捏造证据”。

### 4.2 分层匹配

| 层级 | 处理方式 | 能否作为通过依据 |
| --- | --- | --- |
| 指定范围匹配 | 使用已读取的同一份材料，在指定行区间核实完整引文 | 可以，沿用现有语义边界 |
| 邻近位置修复 | 在同文件有限范围内查找完整引文，要求唯一、连续命中 | 可以，但必须记录修正后的实际行号 |
| 重合度候选定位 | 仅给出疑似相关段落，保留原文和差异 | 不可以直接升级为 `supported` |
| 无法定位或存在歧义 | 保留失败原因 | 维持 `unknown` 或原有不支持状态 |

初版建议只增加邻近位置修复，不引入额外语义模型调用。

### 4.3 邻近修复约束

- 修复窗口使用有上限的配置；可从原起止行各偏移不超过 3 行的小窗口开始验证，这只是初始设计值，不是已证明最佳阈值。
- 路径必须已存在于当前材料集合。不得跨文件寻找相似文本替代缺失文件。
- 严格拒绝布尔值、非整数、反向及越界行号；初版只修复合法范围内的位置漂移。
- 引文必须完整且连续，不能拼接分散段落，也不能自动补全被模型省略的词语。
- 指定位置已经匹配时直接接受；进入容错分支后若有多个可解释位置，则不任意选取一处。
- 不删除否定词、数字、标点、代码符号或链接目标来制造匹配。
- 邻近窗口内未找到时不自动进行无界全文模糊搜索，保留可解释的失败结果。
- 只核验本次送审快照，不重抓新版本后沿用旧评估。

现有连续空白标准化也不能被解释为代码语义等价证明。对于代码块、YAML 和空白具有意义的内容，应保守核验；任何新增容错均不得扩大这类内容的放行范围。对既有空白处理的进一步收紧需通过独立反例测试验证。

### 4.4 审计与展示

建议扩展结构化核验结果，至少包含：

- 模型提供的文件、行号和引文。
- 实际定位到的文件、行号及原文片段。
- 匹配方式，例如指定范围匹配、邻近修复。
- 核验器版本及失败原因，例如路径缺失、行号类型错误、范围越界、引文不一致、定位歧义。

保留模型原始输出，报告展示实际核验位置。不能将修正结果覆盖原始记录，造成模型最初就给出正确行号的假象。

### 4.5 原文存在与能力支持分开

程序证明引文存在，并不证明模型的能力判断正确。例如原文包含“不支持登录后爬取”，模型只引用其中“支持登录后爬取”，仍可能发生断章取义。

应在评估 Prompt 中要求引用足够完整的句子或必要上下文，并在测试中加入否定、条件、范围限制、未来计划和示例性描述。报告不宣称“原文核验通过”等于“功能已实测”或“语义判断完全可靠”。

如未来增加语义复核，应作为单独能力设计并计入预算，不混入字符串匹配器，也不以重合度代替语义复核。

## 5. 实施顺序

| 步骤 | 工作 | 交付条件 |
| --- | --- | --- |
| 1 | 固定需求、材料及正反例，补齐查询和核验失败统计 | 建立可复现基线，不依赖旧机器历史完整性 |
| 2 | 统一查询校验与去重 | 初始、交互和反思路径行为一致，原约束不变 |
| 3 | 术语表和覆盖检查先以观察模式接入 | 能解释会补哪些词、为什么补；不开启额外网络请求 |
| 4 | 启用有界术语补全及结果归因 | 查询上限、去重、预算、续跑通过测试 |
| 5 | 增加结构化核验结果和邻近定位修复 | 原始证据保留，漂移可恢复，反例不误放行 |
| 6 | 更新报告、运行说明和配置说明 | 文档明确已有能力、新增能力及仍未覆盖的问题 |
| 7 | 同预算小批量真实对照 | 实测有效候选、合格结果、成本及错误率，不预设两倍收益 |

查询增强和证据定位修复应有独立开关。先完成离线实现与回归，再单独安排真实搜索和模型验证。

## 6. 指标口径与验收

### 6.1 查询效果

| 指标 | 口径 |
| --- | --- |
| 查询请求数 | 实际网络请求，重试另列；不能只统计去重后的短语数量 |
| 新增仓库数 | 按规范化仓库身份去重后的首次发现数量 |
| 新增 Skill 数 | 已展开确认的技能，按 `skill_id` 去重 |
| 有效材料数 | 成功抓取且可送审的候选数量 |
| 合格结果数 | 经现有标准评估及核验后进入短名单的数量 |
| 查询边际贡献 | 每条查询首次带来的新增候选，同时保留所有发现来源 |
| 成本与时延 | 请求数、限流次数、模型 Token、找到首个及达到目标结果的时间 |

首个发现查询会受执行顺序影响，边际贡献不能当作某条查询的绝对价值。比较时应固定查询顺序或说明顺序差异。

没有已标注的相关技能集合时，只能报告“新增有效候选”，不能直接称为完整召回率。若建立相关集合，召回率为找到的集合内相关技能数除以集合内相关技能总数，并说明集合本身的覆盖限制。

### 6.2 核验效果

- 精确匹配通过数、邻近修复通过数分别统计。
- 对真实引文的错误拒绝，与对伪造或删改引文的错误接受分别统计。
- 区分引文定位错误与模型语义判断错误，不混成单一准确率。
- 除总体结果外，按中文、英文、代码、表格、重复段落、否定句等样本类型检查。
- 不用降低证据标准换取更多 `strong` 结果。

### 6.3 必须通过的回归场景

**查询链路：**

- 中文需求可补充适用的英文技术术语，但不增加用户未要求的硬性能力。
- 已包含英文术语时不重复扩展；大小写和连续空白差异不占用重复查询名额。
- 术语存在歧义时不机械补全；无法命中术语表时正常使用原规划。
- 扩展后不突破查询、轮次和评估预算，反思不循环生成已用词。
- 续跑复用保存的计划、游标及失败计数；术语表升级不会触发重复执行旧查询。
- 多个查询发现同一仓库或技能时只处理一次，保留来源归因。

**证据完整链路（模型原始 JSON → 解析 → 核验 → 排序 → 报告）：**

- 正常跨行及连续空白差异保持现有有效行为。
- 合法行号的小范围漂移能唯一定位，并记录实际位置。
- 重复段落产生歧义时不随意接受。
- 布尔值、浮点行号、越界、反向范围、未读取文件不能绕过校验。
- 删除否定词、改变数字、版本或代码符号的引文不能因高词重合度通过。
- 分散段落拼接、跨文件相似句和模型补写内容不能被当作完整原文。
- 一个必需项证据无效时，不因为其它项目通过而进入强匹配短名单。
- 实际原文与能力判断相反的样本单独检查，明确纯字符串核验的限制。
- 修改原始评估对象、重抓材料漂移和审计字段丢失均有保护。

Windows 本地验证入口沿用项目规范：Python 全量测试使用 `.\.venv\Scripts\python.exe -m unittest discover -s tests -q`；如涉及前端展示修改，使用 `npm test`。

## 7. 涉及模块及实施边界

| 模块 | 预期职责 |
| --- | --- |
| `src/finder/plan.py` | 查询覆盖检查、统一去重、规划与反思提示 |
| 新增术语配置或纯函数模块 | 版本化概念与别名映射、适用条件 |
| `src/finder/search.py` | 查询构造、可控搜索策略与来源信息 |
| `src/finder/refill.py` | 有界执行、游标、去重、归因及恢复 |
| `src/finder/evidence.py` | 完整引文定位、结构化匹配结果及失败原因 |
| `src/finder/evaluation.py` | 调用核验器、保留审计、匹配资格降级 |
| `src/finder/report.py` | 查询效果、实际证据位置及未验证边界展示 |

本方案不重写普通目录的质量引用规则，不自动迁移历史评估结论，也不把 Finder 的容错直接应用到所有文本类型。实施时保留当前用户工作区中的其他改动。

本次仅交付方案文档，不修改业务代码、配置或历史记录，不执行真实联网搜索、模型请求、提交或推送。
