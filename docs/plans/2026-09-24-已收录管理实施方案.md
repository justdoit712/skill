# 已收录 Skill 管理：详细实施方案

日期：2026-09-24
状态：待实施。本文件描述目标行为，不代表功能已完成。
适用项目：个人使用的 Skills 导航目录。

## 1. 目标与已经确认的边界

用户将某个上游 Skill 收录到自己管理的仓库后，在本项目中标记“已收录”，使它不再反复出现在推荐、候选、收藏和定向查找结果中，也不再接受后续自动评估。

以下为已确认的产品决定，实施时不再重复询问：

| 项目 | 决定 |
| --- | --- |
| 使用者 | 默认只有仓库所有者本人；名单是项目级配置，不做多用户账号系统 |
| 隐藏范围 | 主目录和定向查找同时生效，包括此前生成的查找报告在页面中的展示 |
| 有效期 | 持续生效，不自动到期 |
| 上游更新 | 第一版不跟踪已收录 Skill 的更新，不因内容更新重新展示 |
| 标记方式 | 第一版手动标记；仓库扫描、批量识别另行实施 |
| 恢复 | 支持取消已收录；恢复原有展示规则，不强制升级为推荐 |
| 身份 | 按上游仓库和 Skill 路径匹配，不按名称匹配，不做整库连带隐藏 |
| 隐私 | 管理仓库链接和个人备注不写入公共网页数据 |

本方案的实施选择：已收录名单可以作为公开静态数据的一部分；管理链接和备注只保存在当前浏览器，可单独导出私人备份。项目级隐藏状态可以跨设备同步，私人详情第一版不跨设备自动同步。

“默认只有本人访问”不等于网站有访问控制。第一版不增加登录；公共 JSON 中只放允许公开的字段。

### 1.1 不在本期范围内

- 安装、复制或执行 Skill；点击“已收录”只是声明已完成外部收录。
- 自动扫描个人仓库、解析其中的上游来源。
- 上游版本更新提醒、内容指纹持续检查。
- 同名去重、跨仓库复制品识别、仓库迁移和路径重命名自动追踪。
- 将现有屏蔽名单自动迁移成已收录名单；无法仅凭屏蔽原因可靠推断收录事实。
- 用户账号、服务端私人资料存储、自动提交 GitHub 的浏览器凭据。

## 2. 现有实现与需要补齐的位置

当前页面支持收藏、屏蔽和冷冻，本地状态通过浏览器存储保存，再导出配置同步到仓库。主目录业务位于 `src/catalog/`，定向查找位于 `src/finder/`，两者有禁止互相导入的架构约束。

| 现有位置 | 当前职责 | 本期调整 |
| --- | --- | --- |
| `src/catalog/config.py` | 读取采集配置、执行预检 | 加载已收录名单；错误在任何付费调用前暴露 |
| `src/catalog/local.py` | 本地候选池、采集和评估 | 候选池可执行计数和处理入口均跳过已收录项 |
| `src/catalog/sync_reserve.py` | Actions 发现、排队、抓取、预留 | 新候选及旧队列均在材料抓取和额度预留前过滤 |
| `src/catalog/sync_evaluate.py` | Actions 评估和写出 | 再次检查名单，防止两阶段之间新增标记后仍调用模型 |
| `src/catalog/index.py` | 主索引与页面投影 | 保存名单快照，生成已收录管理数据、可见列表和计数 |
| `src/catalog/maintenance.py`、`store.py` | 离线同步、恢复和存储 | 同步名单；离线恢复不丢失已有名单快照 |
| `src/finder/run.py` | 查找、候选调度、评估 | 在调度截断和材料抓取前过滤；记录跳过数量 |
| `src/finder/report.py` | 本地报告和公共报告投影 | 展示过滤统计，不公开私人详情 |
| `public/js/catalog-state.js` | 收藏、屏蔽和冷冻状态 | 与独立已收录状态配合，保留现有缓存和行为 |
| `public/js/catalog-view.js`、`find-view.js` | 卡片和报告展示 | 两类卡片均提供已收录操作 |
| `public/js/app.js`、`modals.js` | 页面编排和配置同步 | 管理入口、计数、撤销、同步状态及错误提示 |
| `.github/workflows/sync-config-deploy.yml` | 配置变更后离线构建发布 | 增加名单文件触发；增加本功能相关校验 |

不复用 `manual_exclusions` 保存已收录事实。人工排除会影响条目状态，“已收录”只影响个人展示和后续处理资格，两种信息分别维护。

## 3. 核心不变量与状态优先级

### 3.1 必须保持的不变量

1. 标记与取消标记均不改写 `status`、评估证据、内容指纹、原检查时间和待复核标记。
2. 标记已收录不删除主索引、历史报告或额度账本。
3. 已收录项不进入新的候选材料抓取、候选评估和额度预留。
4. 已收录项不计入“本轮新增推荐”目标或“可处理候选”水位。
5. 私人链接和备注不得进入 `data/catalog.json`、公共报告、`public/`、同步配置或运行日志。
6. 同一名单被主目录与定向查找独立读取，两者不互相导入业务模块。
7. 名单配置损坏必须报错，不能当作空名单继续调用模型。
8. 同步后的已收录状态在换浏览器后仍生效；未同步的标记只在当前浏览器生效。

搜索和仓库目录展开有时必须先执行，才能知道仓库包含哪些具体 Skill。因此“不跟踪更新”不承诺零 GitHub 请求；它承诺已识别的已收录条目不会为了检查更新而抓取正文或评估。

### 3.2 展示优先级

默认目录按以下顺序判断：

1. 已收录：从默认列表隐藏，出现在已收录管理列表。
2. 人工屏蔽：沿用已有屏蔽逻辑。
3. 收藏、冷冻、自动推荐或候选：沿用已有规则。

已收录状态可以与收藏、屏蔽和冷冻共存，不自动清除它们。取消已收录后重新按以上规则判断。例如，原来已屏蔽的 Skill 仍不显示，尚未到期的冷冻也仍有效。

定向查找仅新增已收录过滤，不因此继承主目录的领域限制、屏蔽或冷冻策略。

### 3.3 身份规则

使用现有稳定 ID，例如 `anthropics/skills:skills/pdf/SKILL.md`。

- 仓库所有者和仓库名大小写归一化；路径大小写保留。
- 分支、标签、提交哈希和内容指纹不参与已收录身份。
- 同一仓库的另一个路径不受影响。
- 另一仓库中同名或相同内容的 Skill 不受影响。
- 仓库级旧条目仅精确匹配仓库级 ID，不解释为整库通配符。
- 第一版卡片必须有合法 ID 才能标记；缺少 ID 的历史条目提示无法标记，不按名称猜测。
- 对路径拒绝空段、`..`、绝对路径等不合法输入；不静默改写路径含义。

个人仓库的管理链接只是附加资料，不参与隐藏匹配。

## 4. 数据契约

### 4.1 项目级来源名单

新增 `config/owned-skills.json`：

```json
{
  "schema_version": "1.0.0",
  "items": [
    {
      "skill_id": "anthropics/skills:skills/pdf/SKILL.md",
      "name": "pdf",
      "source_url": "https://github.com/anthropics/skills/blob/main/skills/pdf/SKILL.md",
      "added_at": "2026-09-24"
    }
  ]
}
```

| 字段 | 要求 |
| --- | --- |
| `schema_version` | 必填；第一版只接受 `1.0.0` |
| `items` | 必填数组，可为空；按规范化 ID 去重 |
| `skill_id` | 必填，作为唯一匹配依据 |
| `name` | 必填非空字符串，管理列表用，不参与匹配 |
| `source_url` | 可选；有值时只接受有效 HTTP(S) URL；只记录上游公开来源 |
| `added_at` | 必填有效日期 `YYYY-MM-DD`，页面按北京时间生成 |

文件不存在时按空名单处理，兼容旧仓库和测试夹具。文件存在但 JSON、版本、字段类型或 ID 不合法时停止当前操作，保留上次有效产物。重复 ID 直接报错，不采用最后一条覆盖。

配置不接受 `managed_url`、`note` 等私人字段，避免用户误把私人详情同步出去。读写时采用固定字段白名单，不把未知字段复制到公共产物。

### 4.2 私人详情

浏览器独立存储键建议使用 `skill_owned_private_v1`：

```json
{
  "schema_version": "1.0.0",
  "details": {
    "anthropics/skills:skills/pdf/SKILL.md": {
      "managed_url": "https://github.com/example/my-skills/tree/main/pdf",
      "note": "已调整为自己的工作流程"
    }
  }
}
```

只允许页面读取该浏览器存储；不发送到 GitHub 配置编辑页，不进入正常配置下载。编辑框明确提示“仅保存于当前浏览器，不随名单同步”。清除浏览器数据会丢失私人详情。

提供独立的“导出私人备份”和“导入私人备份”，文件名为 `owned-skills.private.json`。导入按 ID 合并，遇到本地与导入内容冲突由用户选择保留本地或使用导入值，不改动已收录状态。该备份不放进项目 `public/`，也不纳入部署流程。

管理链接只允许 HTTP(S)，拒绝脚本协议和包含用户名密码的 URL；备注作为文本渲染。取消已收录保留私人详情，方便误操作恢复；明确删除私人详情是单独操作。

### 4.3 主索引与公共投影

`data/catalog.json` 增加 `owned` 名单快照，不将已收录编码为条目 `status`。快照用于保证离线恢复与页面生成具有同一输入。

`public/data/catalog.json` 增加：

- `owned`：来源名单及版本；按白名单生成。
- `owned_entries`：已有主目录条目的展示快照与原分区信息，用于管理及立即恢复。
- `counts.owned`：名单总数，包括仅来自定向查找、尚未进入主目录的条目。
- `counts.owned_in_catalog`：已收录且存在于主索引中的数量。

默认 `recommended`、`candidates`、`manual` 数组排除已收录项，分区计数与数组一致。分类筛选计数基于当前可浏览目录计算，不能把隐藏的已收录项算入。

`owned_entries` 中保留的是原始展示事实，不生成新评估。被屏蔽或非展示状态的条目仍可管理，但取消已收录不能把它们变成候选或推荐。前端要按显式原分区恢复，不使用“其他状态默认进入候选”的兜底。

仅来自定向查找的记录可以独立存在于名单。取消后可在原查找报告重新展示，但不会凭空添加到主目录。

### 4.4 前端状态与配置变更包

新增独立模块 `public/js/owned-state.js`，避免修改已有收藏缓存格式。建议状态包含：

- `baseline`：页面加载的已同步名单。
- `changes`：当前浏览器尚未同步的增加、修改、删除。
- `privateDetails`：私人详情，独立持久化。

有效名单 = 基线应用当前浏览器变更。新增后立即取消应抵消该次新增，而不是产生一条虚假删除。对已同步记录取消则记录删除操作。

同步使用带逐条前置条件的变更包，避免旧页面导出整个名单覆盖仓库中的新记录：

```json
{
  "schema_version": "1.0.0",
  "changes": [
    {
      "skill_id": "anthropics/skills:skills/pdf/SKILL.md",
      "before": null,
      "after": {
        "skill_id": "anthropics/skills:skills/pdf/SKILL.md",
        "name": "pdf",
        "source_url": "https://github.com/anthropics/skills/blob/main/skills/pdf/SKILL.md",
        "added_at": "2026-09-24"
      }
    }
  ]
}
```

`before=null` 表示预期不存在，`after=null` 表示删除。后端比较当前记录与 `before`：相等则应用；当前已等于 `after` 则视为幂等成功；其他情况报冲突，整批不写入。未涉及的仓库记录原样保留。

## 5. 后端分层与处理流程

### 5.1 通用模块

新增 `src/shared/owned.py`，仅包含数据校验、ID 匹配、变更包合并和公共字段投影等纯函数。不得读文件、访问网络或导入 `catalog`、`finder`、`infra`。

新增 `src/infra/owned.py`，负责读取名单，复用 `infra/files.py` 的文件读写与锁。业务入口显式传入配置目录，不能隐式固定为进程当前目录。

运行开始加载一次名单，形成该次运行快照。Actions 两个阶段分别加载；已启动的同一阶段不热更新配置。用户在运行过程中标记并同步，最迟从下一次启动的阶段或运行生效，不能撤回已经发出的请求。

### 5.2 本地采集

`prepare_pool()` 计算可处理候选水位时排除已收录项，防止池里大量已收录条目阻止补充候选。

`process_candidate()` 在正文抓取、候选计数和额度处理前检查已收录状态：

1. 记录 `skipped_owned`，本轮按 ID 去重计数。
2. 不调用正文抓取和模型评估。
3. 不把候选永久写为排除或已完成，取消标记后仍可按原规则处理。
4. 本轮报告的新增推荐清单不包括已收录项。

当候选全部已收录时正常结束，并展示对应原因；不能不断补水形成无界搜索。沿用现有搜索、候选和 Token 上限。

### 5.3 Actions 阶段一：发现与预留

`prepare()` 同时处理新候选与上次待办：先按已收录名单排除，再计算抓取上限、队列顺序和额度预留。

待办采用“保留但本轮不可调度”策略：将已收录待办合并保留在持久化待办队列，执行队列只含未收录项。不能只删掉旧队列条目，否则取消标记后可能丢失尚未进入主目录的候选。

报告区分待办总数、可调度数量和已收录跳过数；调度公平轮转只针对可调度集合，已收录项不占抓取名额。

### 5.4 Actions 阶段二：评估与保存

`_evaluate_queue()` 在检查或发起新模型请求前再次判断已收录状态；`_build_evaluated_catalog()` 对这些条目保留旧条目，不能用“本轮未评估”覆盖原评估。

预算按现有预留机制处理：

- 尚未预留的已收录项不新增预留。
- 已预留、随后才标记的条目跳过调用，保留原预留与历史记录；第一版不新增退款或释放额度逻辑。
- 不将跳过伪装为评估成功，不删除已知用量或未知用量记录。
- 待办继续保留，取消标记后遵循原来的重试、周额度和恢复规则。

因此“没有新增评估费用”不等于“已经预留的本周名额会返还”。这一点需写入运行说明。

### 5.5 定向查找

`execute_find_skill()` 在规划模型调用前读取并验证名单。仓库搜索和展开完成后：

1. 保留 `candidates_found` 作为发现总量。
2. 过滤已收录项，记录 `search.skipped_owned` 和对应来源 ID。
3. 对剩余候选执行公平调度和数量截断。
4. 只为剩余候选抓取材料和调用模型。

过滤必须在调度截断前完成，避免已收录项占满候选上限，导致真正未收录的候选被遗漏。

发现结果非空、过滤后为空时，新增 `stop_reason=all_candidates_owned`，状态为正常完成，CLI 返回 0，报告提示“本次发现的候选已全部收录”。若同时存在搜索覆盖不完整，继续显示覆盖不足，不声称全网候选均已收录。

其他空结果、搜索失败、展开失败、材料失败、预算停止和用户中断保持现有语义。适配报告收尾、公共快照发布条件和前端文案，不能只新增一个常量。

历史本地 `report.json`、Markdown 和 `evaluated_count` 不追溯改写。页面展示已有报告时按当前名单过滤，明确区分原报告数量与当前可见数量。

### 5.6 离线同步和恢复

扩展 `--sync-config`：校验名单，更新主索引的 `owned` 快照，原子生成页面投影；不联网、不读模型凭据、不改预算。

`build_catalog()` 的所有调用方都要显式传递或保留 `owned`。重点检查本地逐条保存、Actions 写出、离线增强和已完成记录恢复，防止重建时把名单字段遗漏。

纯投影恢复使用主索引中已提交的名单快照；应用最新配置由 `--sync-config` 负责。两者不混用，保持现有恢复语义。

继续采用主索引和派生页面分别原子写入，不宣称多文件事务。页面写出失败时保留主索引，并给出离线恢复路径。

## 6. 页面交互

### 6.1 标记已收录

推荐、候选、收藏和定向查找卡片均增加“✓ 已收录”按钮。点击直接标记并隐藏，显示短提示和“撤销”；不要求额外确认。私人链接和备注通过管理列表可选补填，不阻塞标记。

刷新当前分区、所有分区徽标、查找徽标和筛选计数。不能仅删除当前 DOM 卡片而留下过期计数。

存储失败时显示“本次修改尚未保存，刷新可能丢失”，保留当前内存状态并允许导出；不提示已永久保存。

### 6.2 已收录管理列表

增加独立分区“已收录（N）”，提供名称、上游来源、收录日期、私人详情编辑和恢复操作。支持按名称、来源 ID、备注搜索；备注搜索仅在浏览器中进行。

仅来自查找的记录、原条目已不在主索引的记录仍可管理，不因找不到目录卡片而丢失。

恢复操作的文案为“取消已收录”，随后提示实际结果：已恢复展示、仍处于屏蔽/冷冻状态，或等待后续采集。不能保证所有记录取消后立即出现在推荐区。

### 6.3 历史查找报告

页面对原报告生成临时可见投影，不能就地修改原对象，避免切换分区和恢复操作后无法找回原数据。

显示“原报告推荐 X 项，当前可见 Y 项，已收录隐藏 Z 项”。全部隐藏时提示“本报告中的条目已全部收录，可在已收录中管理”。未知报告版本仍执行现有版本检查，不能绕过校验渲染。

### 6.4 私人详情与同步分离

管理弹窗把“已收录状态（需要同步）”与“管理链接/备注（仅本浏览器）”明确分开。修改私人详情不会增加仓库配置待同步数量。

私人备份单独导出，正常变更包不包含任何私人字段。页面不得因为填入私人链接而自动导航、抓取链接内容或探测仓库。

### 6.5 浏览器缓存迁移和同步完成判断

使用独立版本化存储键，不清空或迁移现有 `skill_overrides_v2`。

重新加载公共名单后，逐条比较待同步变更：服务端基线已等于目标值则清除对应待同步项；否则继续保留。不能在复制或下载完成时就标记“已同步”。

同浏览器多标签页通过 `storage` 事件更新状态；存在冲突时重新读取并提示，避免旧标签页静默覆盖新标签页修改。私人详情缺失不能被当作用户主动清空。

## 7. 配置落盘与发布

### 7.1 本地同步入口

新增薄 CLI `tools/manage_owned.py`，建议提供以下接口；命令为待实现设计，不代表当前可用：

```powershell
# 检查页面下载的变更包，不写文件
.\.venv\Scripts\python.exe tools/manage_owned.py --check-changes <变更包路径>

# 合并变更，并离线更新目录和页面
.\.venv\Scripts\python.exe tools/manage_owned.py --apply-changes <变更包路径>
```

CLI 不放业务规则；校验、合并与离线同步通过相应模块完成。使用与目录写入一致的项目锁，锁覆盖读取当前配置、比较前置条件、写入配置及重建产物。校验任一项失败或冲突则整批不修改配置。

配置写入成功、页面生成失败时明确报告分阶段结果，提示重新运行现有 `--sync-config`，不要将部分成功描述成完全回滚。重复应用同一变更包应幂等。

常规 Git 提交推送由用户执行或在明确授权的操作中执行。页面不持有仓库写入令牌。

### 7.2 静态页面同步入口

同步弹窗新增“已收录”页签，展示待同步数量及来源变更，提供下载变更包和复制本地命令。与已有收藏、冷冻的全量配置导出明确区分。

第一版不提供未经合并就覆盖整个 `owned-skills.json` 的“一键保存”，避免旧网页覆盖其他设备已同步的名单。熟悉 Git 的用户仍可手工编辑配置，离线校验和部署检查必须覆盖这一路径。

### 7.3 Actions

`sync-config-deploy.yml` 增加 `config/owned-skills.json` 路径触发。顺序为：检出 → 安装运行依赖 → 配置校验/本功能回归 → 离线同步 → 提交派生产物 → 上传同一次构建的静态产物 → 发布。

配置更新与完整采集工作流要审查共同写入和部署顺序。Git rebase 只能合并文件，不能证明旧公共产物对应最新配置：若提交前发现配置基线变化，应重新加载并离线生成，或终止后重跑，不能继续上传旧产物。

统一或协调相关发布入口的顶层并发控制，避免旧构建在新构建之后发布；被调用的部署工作流不重复获取同一组锁。上线验收需验证最终部署产物中的名单版本与预期配置一致。

此次功能实现不自动启用定时采集，也不把本地测试通过描述为已完成远端发布。

## 8. 异常与兼容行为

| 场景 | 预期行为 |
| --- | --- |
| 旧仓库没有名单配置 | 按空名单运行，保留原行为 |
| 旧页面数据没有 `owned` | 按空基线加载，浏览器待同步记录仍有效 |
| 名单 JSON 损坏或未知版本 | 报错停止，保留上次有效产物，不发出模型请求 |
| 非法或重复 ID | 校验失败，不覆盖配置 |
| 变更包与最新配置冲突 | 指明冲突来源 ID，整批不写，刷新或重新生成变更包 |
| 候选已排队或预留后才收录 | 下一阶段跳过；保留候选、历史和已有预留 |
| 已收录条目不在主索引 | 仍可管理；取消不自动生成推荐结果 |
| 原来已屏蔽或冷冻 | 取消已收录仍遵循原规则 |
| 浏览器存储不可用 | 显示未持久化状态，允许导出当前操作 |
| 清除浏览器数据 | 已同步名单可重新加载；未同步修改和未备份私人详情丢失 |
| 页面生成失败 | 保留权威配置/主索引，提示离线恢复，不请求模型 |
| 已有报告全被过滤 | 提示全部已收录；不误报查找失败 |
| 上游移动路径或换仓库 | 视为新身份；第一版需要重新手动标记 |

## 11. 验收用例

### 11.1 数据和匹配

- 同一 ID 的上游内容指纹、分支或名称改变，仍被隐藏。
- 同名不同仓库、同仓库不同路径仍可见；大小写规范与既有 ID 规则一致。
- 未知版本、错误类型、重复 ID、非法日期和路径均拒绝。
- 名单不存在时兼容；名单错误时不触发模型调用。
- 私人字段不能进入配置变更包或公共投影。

### 11.2 主目录处理

- 已收录候选的抓取和评估替身均设为“被调用即失败”，验证本地与 Actions 都不调用。
- 阶段一预留后新增已收录标记，阶段二跳过；额度记录未被伪造或删除。
- 原推荐的评估字段在标记、离线同步、恢复后保持一致。
- 待办保留、过滤水位和公平调度正确；取消后重新获得处理资格。
- 离线增强、逐条保存、完成记录恢复不丢失名单快照。
- 默认数组、徽标和分类统计一致，已收录与其他列表没有重复展示。

### 11.3 定向查找

- 使用完整入口替身：规划、搜索和展开正常返回，候选全部已收录时正文抓取与评估均为零。
- 全收录返回正常完成与明确原因，保留真实规划 Token 用量。
- 已收录候选位于调度上限之前时，后面的未收录候选仍能进入调度。
- 搜索部分失败且所有已发现候选都收录时，仍提示覆盖不足。
- 不读取目录排除、收藏、池和周额度，不写主目录文件。
- 历史报告在页面中隐藏/恢复正常，原评估计数和原始对象不变。

### 11.4 页面与同步

- 四类卡片都可标记，立即隐藏、计数更新，撤销后恢复原逻辑。
- 刷新、切换分区、关闭重开浏览器后，已保存状态仍有效。
- 仅查找结果条目也可管理，取消后不出现在无依据的主目录分区。
- 重复导入同一变更包幂等，过期变更包冲突不覆盖其他记录。
- 多标签页的变更不静默丢失；已同步变更自动消除待同步标识。
- 存储失败有提示；私人备份导入导出不改变名单状态。
- 用独特的测试私人链接和备注扫描生成的所有公共文件，确认均不存在。
- 现有收藏、屏蔽和冷冻状态及其导出功能无回归。

### 11.5 验证命令与证据

当前基线：本会话此前实测 Python 320 项、前端 12 项通过。这只是实施前基线，不能作为新功能验收结果。

实施后执行：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -q
npm test
git diff --check
```

另在临时项目副本完成配置变更 → 离线同步 → 页面加载 → 标记/恢复的浏览器冒烟，避免污染实际目录数据。不调用真实付费模型来验证跳过规则，使用会在错误调用时失败的替身。

远端 Actions、GitHub Pages 部署和跨设备实际访问单独记录：未执行就标明未验证，不能从离线测试推导为已上线。

## 12. 回滚与交付

功能回滚时保留名单配置与私人备份，先停止发布混合版本产物，再恢复兼容的代码及页面。清空名单属于取消全部已收录，不是普通代码回滚；不得自动执行。

交付应包含：实现代码、测试结果、实际执行的浏览器检查、更新后的操作说明，以及本方案各阶段的完成状态。实施前重新检查工作区，保留用户已有修改；本轮没有编辑此前检测到修改的 `tests/test_docs.py`。

本期最终用户流程：发现 Skill → 在个人仓库完成收录 → 页面点击“已收录” → 导出并应用变更 → 同步发布 → 主目录和定向查找不再重复推荐。
