# LLM 评估流水线与 Token 成本优化方案

日期：2026-09-27  
状态：待实施方案；本文记录代码审查结论及建议，不表示相关功能已经实现。  
范围：以 Windows 本地普通目录评估入口 `tools/run_local.py` 为主，兼顾现有预留、评估、账本和报告契约。

## 1. 目标与结论

在保持证据可核验、评估结果可追溯、预算记账完整的前提下，减少无效模型调用，提高单位 Token 获得的有效评估数量。

| 原始优化项 | 审查结论 | 调整后的方向 |
| --- | --- | --- |
| AST/Markdown 语义规范化指纹 | 有价值，但不能证明任意 Markdown 改动语义等价，也不能直接替换原始指纹 | 增加保守、带版本的规范化辅助指纹，复用前重新核验证据 |
| 静态质量启发式过滤 | 有价值，但行数及 Frontmatter 不足以单独决定质量 | 明确空壳拦截与软性优先级分开处理，先观察误判再启用 |
| Native JSON Schema 支持 | `json_object` 已实现并在审查时的配置中启用；严格 Schema 尚未实现 | 按后端能力接入完整 Schema，保留本地校验和失败分类 |

“节省 15%～30% 重复重评 Token”仅是原提案中的收益假设，当前没有本项目样本支撑，不能作为已实现效果或确定性承诺。

## 2. 已核实的现状

### 2.1 指纹与评估缓存

- `src/shared/identity.py` 的 `content_fingerprint()` 对原始文本计算 SHA-256 摘要，`src/catalog/dedupe.py` 引用该函数。
- `src/catalog/evaluation.py` 的 `evaluation_id()` 由技能 ID、内容指纹、规则版本、模型配置版本组成。
- `src/catalog/local.py` 会在读取材料后查询已完成账本，匹配时直接复用。因此系统已具备精确内容缓存，并非每次发现上游变更都会无条件调用模型。
- 换行、空行等文本变化可能改变原始指纹；当前没有专门的格式规范化复用层。
- `src/shared/materials.py` 保存原始材料指纹及材料集合指纹。普通目录目前评估主文件；不能假设已读取主文件引用的其他文件。

### 2.2 预筛与调度

- `src/catalog/prescreen.py` 已处理人工排除、DSH、模板或占位命名、范围外来源等规则。
- 文本少于 200 字符时会添加 `CONTENT_MAY_BE_EMPTY` 标记，当前不单凭长度排除。
- `validate_document()` 已检查空内容、HTML 页面和文档路径；本地主流程另检查抓取截断。
- 本地主流程以单个候选为单位完成抓取、预筛和评估，尚无基于一批正文质量的评估排序。
- `src/catalog/queue.py` 已有复核、人工项、来源及等待时间等排序依据。新增质量信号不能无意覆盖已有业务优先级。

### 2.3 结构化输出与重试

- `src/infra/llm.py` 已从 `request.response_format` 读取配置，并构造 `{"type": 配置值}`。
- 审查时本机配置为 `request.response_format="json_object"`。这是配置与请求构造事实，不代表已验证服务端对所有输出的保证。
- 当前构造方式不能直接传入完整的 `json_schema` 对象。
- `OutputJsonError` 表示正文不能解析为合法 JSON；字段结构错误另有分类。输出截断由 `finish_reason=length` / `LENGTH_EXCEEDED` 单独处理。
- 当前本地失败策略不会对格式错误和截断无条件自动重试；因此不能把本项目现状概括成“JSON 不合法就反复付费重试”。

### 2.4 预算口径

周额度账本主要管理评估名额及尝试次数，本地运行还管理累计 Token 停止阈值。报告应分别展示名额、HTTP/模型请求数和 Token 用量，不将它们统称为“每周 Token 预算”。

## 3. 实施原则

1. 保留原始材料及其精确指纹，规范化只能增加辅助信息。
2. 缓存复用不能绕过规则版本、模型配置版本、独立复核、人工覆盖或证据要求。
3. 缺少 Frontmatter、篇幅短或排版简单，不单独构成质量不合格。
4. 技术错误、材料缺失、静态规则命中和模型质量判断分别记录。
5. 所有实际请求继续计入既有预算；缓存命中不伪造模型调用、用量或新的评估时间。
6. 优化首先支持观察模式和独立关闭开关，出现误判时可回退到现有流程。
7. 实施与测试默认使用本地材料、临时目录及模拟接口；真实后端校准单独安排。

## 4. 优化一：保守的规范化缓存

### 4.1 数据设计

建议新增以下信息，最终字段位置在实施时结合材料契约确定：

| 字段 | 用途 |
| --- | --- |
| `content_fingerprint` | 现有原始指纹，含义保持不变 |
| `normalized_fingerprint` | 经允许的规范化转换后得到的辅助指纹 |
| `normalization_version` | 规范化算法版本，变化时旧辅助索引不能直接复用 |
| `reused_from_evaluation_id` | 指向被复用的已完成评估记录 |
| `reuse_audit` | 保存转换类型、证据核验结果和本次复用时间 |

规范化逻辑宜放在独立的纯函数模块中，由目录流水线调用。`dedupe.py` 继续负责候选身份合并，避免把材料转换、缓存查找和账本操作全部塞入该模块。

### 4.2 规范化边界

初版只考虑能够明确说明等价条件的转换，例如标准文本换行编码差异；复杂转换先只观察，不自动复用。

不得直接执行以下全局清洗：

- 对全部行统一 `strip()`，删除缩进或行尾空格。
- 合并任意空行，忽略列表、段落和代码块结构。
- 删除 HTML 注释或代码注释。评估对象是提供给模型的材料，注释也可能含指令或风险内容。
- 抹平标题层级，删除链接目标、锚点、查询参数或文件路径。
- 对代码块、YAML 多行字符串、表格或命令参数任意折叠空格。

后续如引入 Markdown AST，必须保留节点类型、层级、代码、链接目标及其他送审内容，并明确方言与解析器版本。AST 相同只能作为预先定义的结构等价信号，不能自动宣称具有完整语义等价性。无法可靠解析时回退到精确缓存或正常评估。

### 4.3 复用流程

1. 抓取并验证当前材料，保留精确指纹。
2. 优先查询现有精确缓存。
3. 未命中时计算规范化指纹，查找同技能且规则、模型配置、输出契约、规范化版本兼容的已完成记录。
4. 验证记录完整性及原有复核状态。失败、处理中、用量未知、待复核记录不作为完整结果复用。
5. 将历史引用在新原文中重新定位，核实引用文本，并检查相关材料集合是否一致。
6. 有歧义、引用无法核实、所需旧材料缺失或版本不兼容时，回退到正常评估。
7. 复用成功后保存独立的复用审计，保留原始评估时间、来源记录及当前材料身份，不能冒充新做了一次模型评估。

引用可能因空行变化产生行号漂移；若规范化改动影响引用文本本身，初版不自动改写证据来强行通过。涉及独立复核的结果，初评与复核中的相关证据都应核验。

若日后评估输入扩展至参考文档或脚本，缓存身份必须覆盖全部实际送审材料，不能仅以 `SKILL.md` 未变化判定可复用。

### 4.4 收益限制

计算新指纹仍需要获得新内容；这项优化主要减少模型重评，不直接保证减少抓取请求。缺失历史原文时不反推旧规范化指纹，旧记录继续沿用精确缓存，新样本逐步积累。

## 5. 优化二：静态分级与明确空壳拦截

### 5.1 分离“确定性拦截”和“优先级信号”

| 信号 | 建议处理 |
| --- | --- |
| 空文件、HTML 登录页、抓取截断 | 沿用材料无效或抓取失败处理，不伪装成质量淘汰 |
| 仅含标题或明确占位说明，没有实际任务内容及有效材料入口 | 满足完整规则后可跳过模型，记录静态原因 |
| 缺 Frontmatter 或字段不足 | 记录结构提示，不单独排除 |
| 正文不足 10 行或少于某字符数 | 记录短文本信号，不单独排除 |
| 有具体任务、步骤、交付物、验收条件 | 作为排序信号，不直接判定为推荐 |
| 包含 TODO，但同时有实质内容或有效引用入口 | 不因关键词单独拦截 |

“有效入口”不能只凭链接存在就认定内容完整；其作用是避免把可能依赖配套材料的短文档误判为空壳。引用材料尚未获取时，保持待判断状态。

### 5.2 输出与配置

建议输出可解释的结果，包括启发式版本、档位、命中信号、建议动作及原因。优先使用少量档位，例如“正常”“信息不足”“明确占位”，避免把未经验证的分值呈现为准确的质量概率。

长度阈值、占位识别规则和权重由统一配置管理。静态跳过记录与模型评估记录分开保存；规则版本或内容变化后，可以重新检查，不形成永久黑名单。

### 5.3 调度接入

在现有候选池中增加有上限的小批次材料准备：抓取、验证、静态分级并缓存，然后再决定模型评估顺序。

- 不一次性抓取完整候选池；批次大小有上限，仍受现有抓取与停止条件约束。
- 评估使用已准备的相同材料快照，避免排序后再次抓取不同版本。
- 质量档位仅在业务优先级兼容的候选之间调整顺序。
- 加入等待时间或轮转机会，避免低档位候选长期无法评估。
- 同时核对本地候选池和既有队列入口，不能只改 `queue.py` 就认为本地主流程已生效。

### 5.4 启用方式

先以观察模式记录“本来会拦截哪些候选”，不改变调用行为；抽样检查短而有效、无 Frontmatter、以模板交付、依赖参考文件等情况后，再启用明确空壳拦截及排序。

## 6. 优化三：按能力配置严格输出契约

### 6.1 明确能力层级

| 模式 | 本项目要处理的约束 |
| --- | --- |
| 提示词约束 | 本地解析与校验仍必需 |
| `json_object` | 当前已有请求支持；不把它当作字段、类型及枚举的严格契约 |
| `json_schema` | 按明确支持该能力的后端配置完整 Schema；仍需业务及证据校验 |

Schema 无法保证引用真实、判断正确，也不能替代输出额度与截断处理。

### 6.2 接口与兼容性

1. 保持现有字符串配置兼容，新增受校验的结构化配置形式。
2. 将后端能力声明与实际输出 Schema 分开：模型配置说明支持什么，业务调用说明本次期望什么。
3. Schema 来自单一输出契约，与本地解析器共用字段、枚举和版本，避免两套定义漂移。
4. 普通目录评估、定向查找规划、澄清、反思和候选评估的输出不同，不能给整个模型配置套用同一份业务 Schema。
5. 缓存身份应纳入输出契约变化，避免新契约误用旧结果。
6. 服务端不支持格式参数时返回明确配置或能力错误，不能每个候选都先失败一次再偷偷降级重发。
7. 若确需回退模式，应在运行开始前确定，并记录实际采用模式；未知用量与中断请求仍遵守既有恢复规则。

本方案不预先认定当前后端支持严格 Schema。真实能力确认需要独立的小样本请求，并统计实际用量；不能仅根据模型名称推断。

## 7. 执行顺序与交付物

| 步骤 | 工作 | 交付与完成条件 |
| --- | --- | --- |
| 1 | 补齐成本、失败及缓存统计 | 明确指标口径，已有用量记录可汇总；缺失字段标未知 |
| 2 | 建立静态分级观察模式 | 输出命中原因；不改变当前评估结果，完成反例检查 |
| 3 | 启用明确空壳拦截与批内排序 | 材料缓存、队列公平性和恢复逻辑通过回归 |
| 4 | 增加规范化辅助指纹观察模式 | 原始指纹不变，记录潜在命中与无法复用原因 |
| 5 | 启用受限的规范化结果复用 | 完整版本约束、证据复核、复用审计和回退路径通过测试 |
| 6 | 扩展严格 Schema 请求契约 | 离线载荷测试通过，既有字符串配置兼容 |
| 7 | 小批量真实验证 | 在明确安排的联网测试中确认后端兼容性、成本和质量变化 |

每项优化可独立开启和关闭。步骤 6 的离线开发不依赖旧运行历史；步骤 7 的收益结论需要新样本。历史数据缺失不阻塞代码实现，但阻止未经验证的节省比例结论。

## 8. 指标与验收方法

### 8.1 统一指标

| 指标 | 口径 |
| --- | --- |
| 模型请求数 | 所有实际发送请求，含初评、复核、重试；缓存复用不计为请求 |
| Token 消耗 | 服务端返回的输入、输出和总量，推理用量按提供方口径单列，避免重复相加 |
| 未知用量 | 单独统计请求数及预算预留，不当作零成本 |
| 格式失败率 | JSON 解码或结构失败次数 / 对应阶段已收到正文的响应数；同时报告分子分母 |
| 截断率 | 截断响应数 / 对应阶段返回响应数，与格式失败分开 |
| 精确缓存命中 | 复用完全相同材料身份的结果次数 |
| 规范化潜在命中与实际命中 | 分别统计找到候选历史记录、通过全部复用条件的次数 |
| 静态跳过与误拦截 | 按规则统计数量，并报告抽样复核中的有效技能误拦截情况 |
| 单个完成评估的平均成本 | 总用量 / 完成评估数，明确是否包含独立复核 |
| 单个新增推荐的成本 | 总用量 / 新增推荐数；分母为零时标记不可计算 |

没有价格及计费口径时只报告 Token，不推算真实 API 金额。没有实际对照时，“避免的 Token”只能作为标注假设的估算，不能当作精确节省。

### 8.2 必须覆盖的回归场景

- 允许的格式转换命中辅助指纹，但原始指纹继续变化且可追溯。
- 代码缩进、Markdown 硬换行、链接目标、标题层级、YAML 字符串、注释中的指令变化不会错误复用。
- 增加空行后引用正确重新定位；重复引用或引用缺失时回退。
- 规则、模型配置或输出契约变化后，旧结果不能越过版本边界。
- 待复核、未完成、用量未知结果不被包装成已完成评估。
- 短而有效、无 Frontmatter、正文含 TODO 的真实内容不会被单一阈值排除。
- 明确占位条目可以免模型处理，内容更新后能重新检查。
- 排序保持人工规则与已有复核优先级，低优先级条目有获得处理的机会。
- 批次准备、缓存写入和复用落盘中断后可恢复，不重复计费、不重复统计推荐。
- 旧 JSON 配置正常工作；不同业务阶段发送不同 Schema；不支持的后端不会触发隐式付费降级。
- 格式错误、截断、网络错误和未知用量保持现有分类及预算语义。

### 8.3 上线判定

先验证正确性，再比较成本。同一组固定材料、规则、模型及配置下，对比各优化开关；保留短文本、复杂 Markdown、风险指令和引用漂移等反例。

若发现错误复用、有效候选被确定性排除或预算记录失真，关闭对应优化并修复后重新验收。固定回归样本通过不等于已证明对所有上游内容均无误判，启用后仍需抽样检查。

| 模块 | 预期职责 |

| `src/shared/identity.py`、新增规范化模块 | 原始及辅助身份计算 |
