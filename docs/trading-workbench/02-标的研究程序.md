# 标的研究程序：产品与实现规范

版本：0.1.0（设计基线）  
日期：2026-10-09  
状态：待实现。本文描述独立的 PC 研究程序，不是现有 Skill 目录的新增交易执行功能。

关联文档：[交易记录与复盘程序](01-交易记录与复盘程序.md) · [共享数据存储与访问规范](03-共享数据存储与访问规范.md)

## 1. 产品定位

用户提供一个标的和交易意图，程序整理可追溯资料，agent harness 形成围绕该交易周期的研究报告。目标是检验机会与判断依据，明确反证、缺失信息和后续观察条件。

第一版支持 Windows PC 上的 A 股普通股票研究，不做主动选股、全市场扫描或持续推送。用户自行选择标的；加密合约、美股及手机端接入后续再设计。

用户在 Codex 或 Antigravity 的聊天界面发起研究。两个 harness 通过 MCP 读取本地资料、调用采集工具、保存研究成果。程序本身提供资料管理、报告查看和导入导出，不在第一版嵌入 agent 聊天界面。

## 2. 已确认需求与设计选择

### 2.1 已确认需求

- 以分析用户指定标的为起点。
- 每次研究按用户本次交易周期组织；没有明确周期时追问一次。
- 默认自动获取可用资料，用户可以补充截图、新闻和自己的理由。
- 展示资料来源、信息时间和关键缺口，资料不足时不假装已经完成验证。
- 允许参考个人交易复盘，但标的分析和个人执行提醒分开。
- 不因为几笔历史亏损就自动过滤某类机会。
- 研究报告存本地、保留版本；用户主动将报告关联给交易档案。
- 报告中的观点不自动成为用户的交易理由。

### 2.2 本文采用的实现设计

采用共享数据规范定义的记录服务、附件存储、精确版本引用及 MCP 工具。首版以结构化查询和全文检索支持知识库，不把向量数据库作为前提。

行情供应商、公告来源接入方式、图表框架和 UI 框架尚未指定；实现时按实际可获得的数据与许可选择。对接任何服务前需要验证其数据范围、时间精度、复权和更新频率，不能把“可联网”视为“有可靠实时行情”。

## 3. 与记录复盘程序的边界

| 事项 | 本程序 | 记录复盘程序 |
| --- | --- | --- |
| 获取行情、公告、新闻并核验研究假设 | 负责 | 通过明确交接提出问题 |
| 当前标的机会分析 | 负责 | 保存或展示关联报告 |
| 历史时点的研究证据核验 | 负责提供证据与限制 | 负责最终交易过程复盘 |
| 截图成交识别、人工入账 | 不负责 | 负责 |
| 账户持仓、成本、费用、盈亏计算 | 不自行计算 | 提供权威指标快照 |
| 用户交易理由与计划 | 读取用户确认内容 | 负责建立及确认 |
| 个人行为经验 | 引用并生成提醒 | 提炼提案，用户采纳 |

“是否已经持仓”不是划分标准。已经持仓后要求分析新消息，仍属于本程序；事后检查原计划是否执行，属于复盘程序。

本程序不得修改已确认成交、历史原话和个人计划。认为某条个人经验不再适用时，提出复核建议，不直接删除或改写规则。

## 4. 研究任务与运行模型

### 4.1 `research_task` 最小输入

| 字段 | 说明 |
| --- | --- |
| `instrument_ref` | 已确认的交易所＋证券代码；名称歧义需先消除 |
| `question` | 用户原始问题，保留原文 |
| `horizon` | `intraday`、`swing`、`long_term`、`custom`、`unknown`；同时保存用户描述 |
| `mode` | `current` 或 `historical_as_of` |
| `as_of` | 历史研究的信息截止点；当前研究记录运行开始时点 |
| `user_thesis` | 用户的可选判断，与问题和 AI 结论分开 |
| `provided_refs` | 用户提供的截图、文章和既有报告 |
| `personal_context_refs` | 本次明确纳入的交易、计划或经验版本 |
| `data_requirements` | 本次实际需要的信息清单和时间精度 |

周期不明确时任务进入 `WAITING_INPUT`，保存已有问题和资料。可以展示已获得的事实，但正式报告不得暗自把“看一下”解释成日内或长期投资。

### 4.2 任务与运行分离

一个研究任务可以由不同 harness 执行多次。每次执行有独立 `analysis_run` 和输入清单。Codex 与 Antigravity 的报告分别存档，不覆盖成一个无法区分来源的“最终答案”。

任务状态：`DRAFT` → `READY` → `RUNNING` → `COMPLETED` / `PARTIAL` / `FAILED` / `CANCELLED`。缺少用户信息可转 `WAITING_INPUT`。中断后重试创建新 run，保留之前的运行状态。

多个成功报告可以共存；用户可指定首选报告。首选只影响展示，不改变报告内容，也不自动成为交易理由。

## 5. 标准研究流程

### 5.1 明确问题

识别标的、交易周期和用户关注点；优先利用已提供内容，不重复追问。周期、标的等会改变研究方向的歧义一次处理一个。

例如：“研究这只股票，准备拿两周，因为我觉得放量突破。”应转成针对波段周期的验证任务；不能自动扩成全面选股或长期估值报告。

### 5.2 制定资料清单

按问题选择数据，不固定每次都做完整的基本面、技术面和宏观长报告。

| 研究问题 | 可能需要的资料 | 关键缺失的处理 |
| --- | --- | --- |
| 是否突破、量能是否变化 | 明确周期的价格与成交量序列、复权口径 | 只有截图时注明无法完整核验 |
| 事件是否改变判断 | 原始公告、发布时间、相关经营信息 | 新闻转述与原公告分开 |
| 估值或基本面依据 | 报告期、财务口径、可比对象和价格日期 | 时间不一致时不直接比较 |
| 持有计划是否仍基于原假设 | 原研究版本、新信息、用户周期 | 不能把新判断写回旧版本 |
| 历史下单时依据是否充分 | 当时可获得的证据、原始时间记录 | 无历史快照时标记无法复原 |

### 5.3 获取与固化证据

采集通过可替换的数据适配器执行。每份来源至少固化 URL/供应商、取得时间、实际行情时间或报告期、内容摘要、原始文件哈希、可用性和授权保留范围。

agent 通过自身浏览工具取得的资料，也要调用本地工具登记来源；不能只在聊天中出现一个链接，保存报告时却没有对应证据。

没有权限保存全文时，只保存允许保留的片段、链接和元数据。标明证据存档不完整，不能声称未来可完整重现原文。

### 5.4 形成研究判断

每个重要结论分成：

1. 已核实事实：可引用资料直接支持。
2. 分析推断：说明从哪些事实推得，列出替代解释。
3. 待验证假设：尚缺资料，列出验证方法。
4. 失效条件：何种新事实会削弱或推翻判断。

若包含价格区间、量能比较或其他数值，必须注明输入、计算方法和程序生成的数据结果。AI 不凭语言估算替代可重现的计算。

### 5.5 个人经验附加层

默认优先读取用户已经接受的 `lesson_rule`。未经采纳的经验提案只在用户明确要求复查时纳入，并标记为提案。

个人提醒应引用具体历史记录，并限定适用周期和场景。例如“过去三笔类似入场中，两笔发生在你设定的确认条件之前”，而不是泛化为“你不适合突破策略”。

个人提醒独立于标的研究结论，不直接改变筛选、评分或过滤规则。若未来用户要求采用个性化筛选，应单独建立可验证的筛选策略版本。

### 5.6 保存与交接

报告提交经结构、引用、版本、资料覆盖校验后保存。资料不足但仍有价值的结果可为 `PARTIAL`。保存报告不意味着用户认可或已下单。

用户需要关联交易时，在记录复盘程序中选择报告及精确版本；必要时导出交换包再导入。两个程序共用本地库时不重复复制报告，通过主动建立链接完成关联。

## 6. 时间边界与防止事后解释

### 6.1 当前研究

每项资料保留实际数据时间，运行时间不等于行情时间。报告展示“截至某时的数据”和新鲜度。遇到非交易日、延迟行情或供应商故障，应照实显示。

对不同周期配置不同的新鲜度要求，并将采用的要求记入任务。首版不写死所有市场通用的“超过 N 分钟即过期”。

### 6.2 历史时点研究

- `published_at <= as_of` 只是必要条件，还需考虑当时是否实际可获得。
- 后来重述的财报、事后编辑文章、后复权历史价格可能包含未来信息，需记录版本与限制。
- 今天访问到一篇标着过去日期的网页，不能据此宣称恢复了当时页面。
- 只有当前资料时，可做事后解释，但报告明确标为后补研究，不能据此评价用户当时理应知道。
- 分析能力不足以验证历史可得性时，结论为 `UNKNOWN`，不改写证据时间。

## 7. 报告契约

`research_report` 的完整字段遵循共享存储规范。报告正文至少包括：

| 区块 | 内容 |
| --- | --- |
| 任务摘要 | 标的、原始问题、交易周期、研究模式和时间边界 |
| 数据覆盖 | 已取得、缺失、过期、互相冲突的资料 |
| 核实事实 | 每条事实对应来源与位置 |
| 主要判断 | 依据、推断过程、替代解释和不确定性 |
| 反证与失效条件 | 可观察条件，区分研究建议与用户已确认计划 |
| 后续观察 | 需要补充的信息和触发重新研究的事件 |
| 个人执行提醒 | 与标的分析独立，引用历史复盘 |
| 来源清单 | URL、资料时间、取得时间和本地版本 |
| 执行信息 | harness、模型、Skill 版本、输入版本、run ID |

不强制给每个标的输出买卖结论或数字评分。若给出评分，必须另行定义指标、权重、缺失处理和版本；不能让不同 harness 各自发明同名评分。

### 7.1 比较两个 harness 的报告

可以按同一输入清单展示并列报告，列出一致、分歧和证据缺口。对比报告使用新记录保存，引用原报告版本；不以“两个 AI 都这么说”代替证据验证。

第一版不自动组织多 agent 并行分析。用户选择执行工具，数据协议保证结果可互相读取。

## 8. 程序界面

| 页面 | 必须功能 |
| --- | --- |
| 研究任务 | 创建/查看任务、交易周期、问题、状态、运行记录 |
| 资料库 | 原始资料、时间、来源、文件哈希、缺失与冲突提示 |
| 报告列表 | 按标的、周期、日期、harness、状态查询 |
| 报告详情 | 结论到证据跳转、版本比较、后补研究标识 |
| 个人经验 | 只读展示复盘程序已采纳的规则与证据 |
| 交接与导出 | 选择确切版本、导出交换包、查看关联交易 |

用户未启动 AI 时，仍可浏览已有资料、手工建立研究任务、导入导出报告。

## 9. MCP 工具与 Skill

以下为目标接口，统一返回结构见共享规范。

| 工具 | 用途 | 写入边界 |
| --- | --- | --- |
| `research_create_task` | 保存用户问题及研究上下文 | 研究任务 |
| `research_get_task` | 读取任务及输入清单 | 无 |
| `research_collect_sources` | 通过已配置适配器获取资料 | 来源快照、采集状态 |
| `research_register_source` | 登记 harness 自行取得的来源 | 来源快照及受支持附件 |
| `research_compute_features` | 从固定数据快照计算所需特征 | `metric_snapshot`，标记为研究特征命名空间 |
| `research_save_report` | 校验并保存报告 | 研究报告新版本 |
| `research_list_reports` | 按标的、时间、周期等检索 | 无 |
| `research_export_handoff` | 导出指定报告与依赖 | 交换包 |
| `knowledge_search` | 检索本地资料和经验 | 无 |
| `knowledge_get` | 获取精确版本及证据 | 无 |

`research_compute_features` 只计算研究所需市场特征，不承担成交成本、账户盈亏或账本修改。账务指标通过读取记录复盘程序生成的快照获取。

标的研究 Skill 描述：明确周期、建立任务、证据采集、时间核验、事实/推断区分、个人提醒、结果保存及交接。它不能把“当前聊天看过的内容”当作已经落地的数据。

## 10. 失败处理

- 标的歧义：任务保留，追问；不直接抓取同名证券并分析。
- 数据源失效：保存失败事实，必要时使用明确标注的替代来源，不能隐藏切换。
- 多源冲突：并列保存，标明单位、时间、复权或报告期差异；不能静默挑一个。
- 缺乏关键行情：输出局限与待验证问题，报告为 `PARTIAL`。
- harness 中断：运行状态可恢复，原始资料和此前报告保留。
- 重复保存：同幂等键返回原结果，不重复建报告。
- 同时修改任务：要求 `expected_revision`；冲突方重读后再提交。
- 原资料修订：既有报告保持旧引用，展示输入已更新，可按新任务或新 run 重新分析。

## 11. 验收场景

1. 用户提供代码及两周周期，程序正确建立波段研究任务并保留原始问题。
2. 用户未提供周期，AI 追问一次；任务和资料已保存，不能自行假定长期周期。
3. 只有 K 线截图，没有可靠量能序列时，报告明确指出无法完整验证放量。
4. 当前行情与上一交易日收盘数据可清楚区分，报告不把旧数据称为实时。
5. 历史复盘任务取得事后修订信息时，报告标记时间限制，不用于证明当时已知。
6. 用户历史中有执行偏离，报告单独显示个人提醒，标的分析不会被自动删除或过滤。
7. 同一任务由两种 harness 运行，生成不同 run 和报告，均能从本地界面读取。
8. 报告导入交易程序后不自动产生买入理由或成交。
9. 关闭全部 AI 聊天后，程序仍能查到报告、来源和分析版本。
10. 来源获取失败时保存 `PARTIAL` 或失败结果，无伪造来源、时间和数值。

## 12. 实施顺序与依赖

1. 复用共享记录与附件访问层，实现任务、来源快照和报告对象。
2. 建立一个符合实际资料可得性的 A 股数据适配器；先验证字段、时间与复权口径。
3. 完成来源浏览和报告页面。
4. 提供 MCP 工具及研究 Skill，先验证单 harness 完整保存，再验证另一个读取和新增结果。
5. 接入个人经验只读引用和手动交易关联。

第一版不要求先完成复杂自动选股、实时行情平台或多模型编排系统。

## 13. Harness 接入依据

接入方向已经确定为“agent 调用本地程序”，优先使用 MCP。以下文档仅用于确定技术方向，实际安装版本、图片输入能力、权限和传输行为仍须在实现时验证。

- [Codex MCP 官方文档](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)：支持本地 STDIO 等 MCP 接入。
- [Antigravity MCP 官方文档](https://antigravity.google/docs/mcp)：支持连接本地工具、数据库和外部数据服务。

第一版不依赖 App Server/SDK 嵌入，也不承诺两个 harness 使用完全相同的安装配置或模型计费方式。业务数据和工具契约保持一致，harness 配置适配分别完成。
