# 运行说明

## 普通查找的质量优先筛选（2026-09-25）

`tools/run_local.py` 和目录 Actions 共用规则 1.1.0，默认在 `config/standards/rules.json` 启用 `quality_review.enabled`。独立定向查找 `tools/find_skill.py` 不受此次升级影响。

流程：原有预筛 → SKILL.md 六项基础评估及三项质量评估 → 程序核对引用 → 拟推荐项独立复核 → 两轮都通过且主分类一致才推荐。新增三项分别检查具体使用价值、足够明确的步骤/模板/参考内容、可检查的产出要求或验证方法；按技能形态判断，短文档、纯文本技能及低 Star 项目不会因此被机械排除。未提供的引用文件不能当作已读证据，评估不执行上游技能。

原文引用须提供连续完整行及起止行号，程序只验证引用存在，语义支持仍由模型判断。复核是使用当前模型配置的另一独立请求，不接收初评结论；同模型两轮不保证消除共同偏差。普通不合格项通常花一次请求，拟推荐项通常花两次；网络重试和更多候选会进一步增加费用。

每次请求前保存阶段状态，响应后立即保存用量；预算在下一次请求前检查，最后一次请求仍可能超过总上限。初评通过但预算耗尽或响应用量缺失时，保存初评到评估账本的 `pending_evaluation`，保持候选池/队列待处理，下次运行仅继续复核；预算中止不记成质量不合格。运行中断且请求结果不明时仍进入既有恢复机制，不自动重复付费。所有阶段的调用记录保留在账本 `requests`，本地运行报告按请求列出 `assessment` 与 `review`。

规则版本已更新以隔离旧评估缓存；已有目录和本地池中 `done` 的条目不会被本次代码修改自动重评。需要重新发现并检查已有池条目时可用 `tools/run_local.py --refresh-pool`，仍按目标数、预算和发现范围处理，不代表全目录已完成重评。变更质量开关或判据时也应更新 `rules_version`，避免复用不同规则下的缓存。

运行入口保持不变：`.\.venv\Scripts\python.exe tools/run_local.py`。页面仅对新评估显示“筛选依据”；完整初评、复核结论及引文留在本地或 Actions 评估账本。新增规则的真实推荐质量仍需实际模型抽样校准，离线测试验证的是程序行为。

面向运维与维护者。规则与设计的最终依据是 [产品规范](产品规范.md)，
本文**不重复规则内容**，只给出操作步骤与检查点，并标注每个环节对应的需求出处。

参数的唯一入口是 [config/local-run.json](../config/runners/local-run.json)：

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `target_recommended` | `50` | 本次新增推荐数；已有推荐不计入 |
| `max_total_tokens` | `100000000` | 本次输入＋输出 Token 之和；达到后不再发新请求 |
| `max_evaluations` | `null` | 可选评估次数上限；null 允许超过 50，仍受 Token 和候选数量限制 |
| `limit_queries` / `expand_limit` | `null` | 使用配置的全部搜索词并展开仓库；可缩小为抽样运行，查询数 0 表示只使用配置来源 |
| `max_consecutive_failures` | `3` | 连续模型失败达到该数停止 |
| `max_format_failures_without_valid_result` | `10` | 距上次有效结果累计格式异常达到该数停止；避免模型持续吐错空转；可用 `--max-format-failures` 临时覆盖 |
| `max_retries` | `5` | 网络错误、HTTP 408/429/500/502/503/504 最多重连 5 次，加首次共 6 次；可用 `--max-retries` 临时覆盖 |
| `pool_watermark` | `20` | 待处理候选低于此水位线时自动增量搜索补水；充足时跳过搜索秒级启动 |
| `pool_max_age_days` | `7` | 候选池默认有效期天数；超时后自动重新发现并重建候选池 |

**候选池持久化与断点续跑（pool.json）**：
- 初次运行或候选池过期时，完整执行搜索与展开，将发现的全部候选及初始序号（`seq`）固化在 `data/local/pool.json` 中；
- 每处理一条候选（评估通过、预筛排除、抓取失败或非技能文件），立即原子持久化该条目状态（`pending` / `done` / `excluded` / `fetch_failed` / `not_skill` / `length_exceeded` / `blocked`）；
- 若进程中断（或中途达到 Token / 目标限额停止），下次运行**自动从断点继续**，跳过所有已处理候选，绝不从头原地打转；
- 当池中待处理候选充足（>= `pool_watermark`）时，**完全跳过网络搜索**（免去十余分钟耗时与上百次 GitHub API 调用，秒级启动）；低于水位线时自动增量搜索补水并追加到池尾；
- 命令行支持 `--refresh-pool`（重新搜索并重建候选池，保留超长跳过标记）与 `--pool-watermark <N>`（临时调整补水阈值）。

**单条样本异常隔离与容错（超长截断与格式损坏）**：
- **超长截断（LENGTH_EXCEEDED）**：本地目录评估的初评或独立复核返回 `finish_reason=length` 时，按样本级 `LENGTH_EXCEEDED` 处理，不重试、不累加服务连续失败计数，并重置该计数。候选池持久化为 `length_exceeded`，续跑、补水、过期重建和 `--refresh-pool` 均保留跳过状态，不自动重评。截断只表明输出额度不足（可能包含推理 Token），不代表服务不可用，也不代表技能质量不合格；已有目录结论保持不变。
- **输出格式异常（PARSE_ERROR / blocked）**：模型返回空内容、非合法 JSON 或缺少必要字段（输出 Schema 不合法）时，认定为单样本格式损坏，直接标记候选为 `blocked` 并记录到账本，不发起无意义重试，不累加服务连续失败计数，而是平滑跳至下一个候选继续评估。只有在累计 10 次格式异常且中途未产出任何有效结果时，才会按 `format_failures` 机制停止。
- **离线维护工具（manage_pool.py）**：
  - 对账一致性核验：`python tools/manage_pool.py reconcile`（支持 `--dry-run` 预览与 `--apply` 写入修复）。自动将账本已确认超长或不可重试格式损坏的候选同步至候选池 `length_exceeded` / `blocked` 状态。
  - 人工解除阻断：`python tools/manage_pool.py resume --evaluation-id <ID> --reason <说明> [--extra-attempts N]`（支持 `--dry-run` 与 `--apply`）。显式重置指定评估的不可重试状态并同步将池条目恢复为 `pending`。

本次输入、输出及推理用量正常记账，推理 Token 已包含在输出用量内，不重复相加。`report.json` 的 `skipped_length_exceeded` 与 `skipped_output_format` 分别统计本轮超长跳过与格式损坏跳过数，不计入基础设施失败；请求明细保留专属错误码。总预算耗尽、用量未知、候选耗尽等停止条件仍然有效，不能保证一定收满目标数量。

也可临时用 `--target 1 --max-evaluations 3 --limit-queries 0 --expand-limit 3` 小规模运行。
此 Python 入口的总预算取自 `local-run.json`；模型接口、单条输入和输出上限仍取自模型配置。
旧 `scripts/run-local.ps1` / `python -m src.pipeline` 是按评估名额运行的入口，不用于“持续找到 50 个推荐”的新目标。

程序先搜索和展开真实 `SKILL.md`，再按现有规则逐条筛选。仅从上游临时读取 Markdown 原文，
不把 GitHub 网页 HTML 或未展开的仓库首页当技能；不下载或执行技能包。
本轮每个候选最多处理一次；内容、规则和模型配置版本相同的已完成评估会复用。
网络错误及临时 HTTP 错误会自动重试 5 次，等待时间依次为 1、2、4、8、8 秒，控制台显示每次重连与错误类型。
401 等凭据错误、格式解析失败不自动重试。每次请求前持久化尝试次数，响应后持久化用量，
底层接口不再额外重试，避免重试次数相乘。成功后继续处理后续技能；仍失败则停止。
已记录的网络失败在剩余尝试次数内可继续（包括旧版只尝试 1 次的失败）；重跑不重置累计次数。
进程中断留下的 `needs_recovery` 记录仍需人工核查，不能静默重复调用。
达到目标、Token 上限、可选评估上限、候选用完、连续模型失败或最终响应用量缺失也会停止。

**用量与结果**：控制台持续显示输入、输出、总 Token；推理 Token 单列但不重复相加。
每次接口返回后立即保存 `data/local/latest-run.json` 和 `data/local/runs/<运行编号>/report.json`，
后者含每条请求用量；同目录 `report.md` 是可读报告，列出本次推荐链接、分类与简述（完整分类见 JSON 和网页）。
失败响应返回的 usage 也会计入；超时、强制停止等没有返回 usage 的请求记为未知。
为让重试成功后能够继续，未知请求按提示词 UTF-8 字节数＋最大输出 Token＋1024 消息余量预留预算；
`unknown_usage_reserved_tokens` 为估算预留，`budget_tokens` 为已知 Token 加预留，两者达到总上限就不再发新请求。
估算不冒充实际消耗，实际账单以服务商为准。报告同时展示评估数、实际请求数（含重试）和失败请求数。
这不是金额上限，也不是 Token 硬上限：最后一次请求可能使总量超过设置值。

## 4. 队列与复核（§5.2、§5.3、§7.2）

`data/queue.json` 是**跨轮累积**的待处理队列，不是本轮快照。它保证超出每周额度的候选
会在后续运行中依次得到评估，而不是每轮被同一批条目反复跳过。

- 排序：已知内容变化或待复核的条目插队；其余按"先补齐从未处理过的、再按上次检查时间
  从早到晚"公平轮转；同组内官方来源优先。
- 已评估且内容未变的条目**不在队列主体里**：它们只在有多余抓取名额时被抽查
  （`MAX_RECHECKS_PER_RUN`，默认 10 条），用于发现"已推荐内容发生变化"。
  抽查条目在未真正处理时会退回队列，下轮重新排队。
- 队列项记录 `content_fingerprint`（上次抓取到的内容）、`baseline_fingerprint`
  （上次评估到的版本）、`last_attempted_at` 与 `first_queued_at`。
  索引里的指纹优先于队列自己的记录。
- 条目出队条件：这份内容已有完成的评估记录、已达尝试上限，或结果不明需人工确认。
- 建议在运行后确认积压：`--json` 输出的 `queue_pending`（队列长度）、
  `carried_over`（遗留条目数）、`needs_review_backlog`（内容变化积压）。

内容变化后的处理规则见 §5.2：保留推荐状态并醒目标记"内容已变化，待复核"，
同时展示原评估对应的版本与评估时间；复核通过才更新依据并清除标记，
复核不通过降级至候选区。

## 5. 故障处理（§7、§7.3）

| 情况 | 处置 |
| --- | --- |
| 来源不可达 | 保留上次有效数据，**不做**批量删除或虚假下架 |
| 模型调用失败 | 保留待处理状态，**不伪造**中文简介与评估结论 |
| 预留额度后崩溃 | 已预留名额**不释放**；下周重新排队并占用新周名额 |
| 手动重跑 | **不重置**尝试计数；设计上每个名额最多 2 次调用尝试 |
| push 冲突 | 停止后续付费调用、重新加载状态；使用非强制提交，不覆盖他人提交 |
| 提交成功但部署失败 | 只重试部署该产物，**不重新评估**技能 |

- 只管理本项目有权使用的仓库、部署和域名；当前无自定义域名配置，`public/` 不生成 `CNAME`
- `vercel.json`、`.vercelignore` 仍在仓库中；删除前置条件是**核实本仓库没有需要沿用的
  Vercel 自动部署**。该配置输出目录为 `public`，本地文件本身不能证明当前云端绑定关系。

部署检查：确认本仓库的 Vercel 自动部署是否需要使用，再决定上述配置去留；正式发布前确认 Pages 设置、Secrets 与实际工作流结果。

## 9. 人工干预区（收藏与排除黑名单）维护

依据 [产品规范](产品规范.md) §7.4 与 §10.1，所有人工干预统一收敛在 [config/overrides.json](../config/governance/overrides.json)：

### 9.1 人工收藏区（manual_picks）
- **收录条目**：在 `config/governance/overrides.json` 的 `manual_picks` 数组中添加条目对象，包含 `skill_id`（稳定 ID）、`reason`（非空理由）、`added_at`（`YYYY-MM-DD`）以及可选的 `from`（`recommended`/`candidate`）。
- **三区互斥**：收藏条目独立进入「收藏区」，不出现在推荐区与候选区，统计互斥。
- **免自动重评保护**：收藏条目的上游内容变化时更新指纹与检查时间，但**不调用模型重评（0 模型调用）**，程序绝不自动降级或移出。
- **移出收藏**：从 `manual_picks` 数组中删掉对应对象（或清空为 `[]`），该条目立即回到其原始自动结论分区（推荐区或候选区）。

### 9.2 人工排除黑名单（manual_exclusions）
- **永久跳过**：在 `config/governance/overrides.json` 的 `manual_exclusions` 数组中记录被屏蔽的条目对象（包含 `skill_id`、`reason`、`added_at`）。
- **预筛拦截**：预筛阶段直接判定为 `excluded`（原因码 `MANUAL_EXCLUDED`），流水线在发现或爬取到该条目时**完全跳过，0 模型调用、不消耗任何 API Token 额度**，且不出现在推荐区或候选区。

### 9.3 网页端交互与一键同步
无论在本地预览还是 GitHub Pages 线上预览环境：
1. 页面卡片右上角提供 **【★ 收藏】** 与 **【🚫 屏蔽】** 按钮，点击即时在当前页面生效；
2. 页面底部浮动同步栏实时统计未提交的变更项；
3. 点击 **【查看并同步到仓库】**，可直接一键复制最新配置并自动跳转到 GitHub 网页在线编辑页（`https://github.com/justdoit712/skill/edit/main/config/overrides.json`），粘贴后提交即可触发线上自动更新。

### 9.4 已收录名单（owned-skills.json）维护与变更包同步
依据 [已收录 Skill 管理实施方案](plans/2026-09-24-已收录管理实施方案.md)，用于将用户已掌握或私有托管的技能从推荐、候选、收藏及定向查找中隐藏：
- **全局过滤与 0 Token 保护**：标记为已收录后，网页立即从推荐、候选、收藏和定向查找中隐藏条目，不再提供「已收录」分区及数量徽标。同步名单到仓库后，在流水线扫描、候选入池及定向查找展开时均自动跳过抓取与模型评估（0 Token 消耗）。误操作可通过标记后的提示撤销；已同步名单通过仓库配置或 CLI 维护。
- **白名单配置与存储隔离**：公共仓库名单维护在 [config/governance/owned-skills.json](../config/governance/owned-skills.json)，仅包含 `skill_id`、`name`、`added_at` 与可选 `source_url`；历史管理链接（`managed_url`）与私人备注（`note`）仍仅保留在当前浏览器 LocalStorage 中，严禁同步到公共仓库或部署产物。移除已收录分区后，页面不再提供私人详情与备份管理入口。
- **CLI 变更包合并与同步**：使用独立工具 [tools/manage_owned.py](../tools/manage_owned.py) 检查与合入变更包：
  ```powershell
  # 校验网页导出的变更包是否合法、是否有前置冲突（不写文件）
  .\.venv\Scripts\python.exe tools/manage_owned.py --check-changes <patch_file>

  # 加锁合入变更包并离线更新主索引与页面（0 Token 消耗）
  .\.venv\Scripts\python.exe tools/manage_owned.py --apply-changes <patch_file>

  # 查看当前已收录条目
  .\.venv\Scripts\python.exe tools/manage_owned.py --list
  ```
- **工作流自动触发**：向 `main` 分支提交 `config/governance/owned-skills.json` 时，自动触发 `.github/workflows/sync-config-deploy.yml` 运行离线同步与 GitHub Pages 发布。

### 9.5 页面暂存与同步业务场景边界
- **静态部署与单向手动同步**：本站部署于 GitHub Pages 静态环境，无服务端与后台数据库，不支持亦无需自动双向同步。业务同步闭环为：网页浏览 → LocalStorage 本地暂存 → 手动导出变更包或复制 JSON → 提交合入仓库。
- **单页面操作闭环**：单页面内的标记、放弃/清空、导出构成完整闭环。用户点击“清空”即可将当前页面的本地缓存与内存暂存完全清零。
- **杜绝过度设计**：项目不维护脆弱的浏览器跨标签页 Storage 广播实时联动机制；多标签页并发修改或跨页清空属于脱离实际业务形态的边缘用例，所有状态均以当前页面加载与用户显式操作为准。

## 10. 定向查找特定需求 Skill（find_skill.py）

产品约束见 [产品规范](产品规范.md) 第 12 节；实现与验收见 [修复验收记录](audit/2026-09-23-分层重构修复验收.md)。下面描述当前入口和源码行为，不能把目标规范当成已完成保证。

### 10.1 适用场景与运行边界

`tools/find_skill.py` 用于按具体需求比较相关 Skill，例如“生成高质量 Prompt”。它跳过主目录的领域、人工屏蔽与冷冻规则，不修改目录主索引、候选池、队列或周额度账本。它会读取上游材料并调用配置的模型，不安装或执行上游技能。

本地报告保存于独立运行目录，当前也会更新 `public/data/find-report.json`，供页面“定向查找”标签展示。命令本身不提交或发布；后续部署整个 `public/` 时，该报告可能随页面一起上线。

### 10.2 常用命令与参数

```powershell
# 使用配置中的默认需求；配置也未提供 topic 时才交互输入
.\.venv\Scripts\python.exe tools/find_skill.py

# 命令行直传需求与自定义限制
.\.venv\Scripts\python.exe tools/find_skill.py "生成高质量 Prompt" --limit 5 --max-evaluations 20 --max-tokens 200000
```

配置优先级为显式命令行参数 > `config/runners/find-skill.local.json` > [config/find-skill.json](../config/runners/find-skill.json) > 代码兜底值。未提供命令行 topic 时使用配置；两者都为空，仅在交互终端询问输入，非交互环境返回用法错误。

| 参数 | 当前仓库配置 | 代码兜底值 | 含义 |
| --- | --- | --- | --- |
| `topic` | `生成高质量 Prompt` | 无 | 本次查找需求 |
| `--limit` | `5` | `5` | 最多展示的强匹配短名单数 |
| `--max-evaluations` | `80` | `20` | 当前按成功解析的评估数检查，失败不占此计数；修复后按评估尝试计数 |
| `--max-tokens` | `"20 000 000"`，即 20,000,000 | `200000` | 规划与评估合计的已知 Token 停止阈值；最后一次请求可能超过阈值 |

模型连接优先使用 `config/models/model.local.json`，缺失时使用 example；凭据优先从对应环境变量读取。当前规划最大输出 4,000 Token，单技能评估 10,000 Token，连续评估失败停止阈值为 20。读取参数为主文件最多 64 KiB、主文件和最多 2 个引用文件合计 96 KiB。

数值请使用整数；配置中可用空格、逗号或下划线分隔，不要使用 `20m` 等单位缩写。当前非法格式可能静默回退为兜底值，严格校验仍待修复。

### 10.3 报告与当前限制

每次运行输出 `data/local/find-skills/<运行编号>/report.json` 和 `report.md`；JSON 保存需求、固定计划、生效参数、搜索与覆盖信息、请求事实、评估结果及用量。Markdown 为派生报告，公共快照仅在统一收尾按发布条件生成白名单投影，运行开始不覆盖旧快照。

未知用量会停止后续模型调用；当前有效结果仍保留。候选尝试数与成功评估数分别统计，失败尝试占名额。证据须通过严格类型、路径、行号和完整引文核验，但原文匹配不能保证模型的语义判断正确。

搜索、展开或材料全部失败与正常无匹配分别记录；中断收尾保留已有结果。部分查询、仓库或材料可能受读取上限影响，报告会标识覆盖不足，不能将结果称为全网最优。页面不把缺失用量或次数显示为零。

离线恢复命令、旧记录限制及本轮验证结果见 [修复验收记录](audit/2026-09-23-分层重构修复验收.md)，长期接口约束见 [架构约定](架构约定.md)。未执行技能不标记为已通过实测；真实模型语义、远端 Actions 与部署没有因离线回归通过而自动完成验收。
