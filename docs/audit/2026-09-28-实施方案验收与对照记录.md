## 1. 方案背景与目标达成

本项目针对定向查找（Skill Finder）“一直没有推荐结果”、评估流水线异常中断恢复、Token 成本控制与输出格式契约等核心痛点，依据《2026-09-28 综合实施方案》所制订的 10 个独立提交单元进行了完整重构与实施。

### 1.1 核心问题“一直没有推荐”解决确认
- **问题根因**：原 Finder 评估阶段在模型判定候选符合需求并给出匹配评级（如 `strong` / `moderate`）后，需要核对模型摘录的原文引文与起止行号。由于大模型生成引文时经常存在 $\pm 1 \sim 2$ 行的行号偏差或换行差异，原校验器直接断定“引文不存在”并一票否决，将匹配结果强制降级为 `none`，导致最终 shortlist 为 0 条。
- **解决方案（Unit 5）**：在保持严格反篡改、反伪造底线的前提下，引入“两层核验机制”：
  1. 首层执行快速精确行区间匹配；
  2. 若未命中，在原区间上下 $\pm 3$ 行的邻近窗口内执行换行/空白标准化精确滑窗匹配；若匹配成功，标记录得恢复区间（`recovered_line_start`, `recovered_line_end`）并保留有效匹配等级；
  3. 若滑窗仍未命中或引文被伪造/篡改，严格拒绝并降级为 `none`。
- **结果**：成功解决了定位漂移导致的 0 推荐假阴性缺陷，同时杜绝了伪造证据通过。

## 4. 单变量对照实验设计与运行规范

为确保真实环境下的调优可解释、可归因，所有功能均遵循“**默认观察模式（只记审计不改行为），显式命令行开关主动启用**”的设计原则。在进行真实环境对比时，建议每次仅改变一个变量：

```
                              ┌── 默认：观察模式（记录审计字段，不影响模型调用）
[新建特性 (Unit 4/6/7/9)] ────┤
                              └── 显式开关：主动启用（生效优化，安全回退）
```

### 4.1 对照实验对照表

| 优化特性 | 对应 CLI 参数 | 默认行为（观察模式） | 启用后行为（优化生效） | 验证指标与评估点 |
| :--- | :--- | :--- | :--- | :--- |
| **术语有界补全** (Unit 4) | `--enable-terminology-completion` | 记录未覆盖术语至 `terminology_observations`，不增加搜索请求 | 最多补充 2 条英文专业术语检索式（总查询不超过 8 条） | 检查召回候选库质量、新增匹配候选数量与边际 Token 成本 |
| **邻近证据恢复** (Unit 5) | *全时内置安全特性* | $\pm 3$ 行滑窗自动定位恢复，记录恢复标记 | 同左，若未命中或内容篡改则坚决拒绝 | 检查有效推荐短名单召回率，验证伪造证据 100% 拦截 |
| **明确空壳跳过** (Unit 7) | `--enable-static-skip` | 正文分级标记（A/B/C/UNASSESSED）并写入账本，仍调用模型 | 仅拦截确认占位符空壳（`C_PLACEHOLDER`），跳过模型调用 | 检查 Token 节省量、有效短文本技能零误杀率 |
| **批内防饥饿排序** (Unit 7) | *在启用跳过后生效* | 维持原有队列顺序 | 高质量优先，保留 20% 配额防止低级/无星技能饥饿 | 检查推荐成功率与样本多样性 |

### 4.2 异常与回退策略
- **即刻关闭**：若在实跑中发现任何误拦截、证据误放行或复用异常，只需在运行命令中去掉对应开关即可立即回退至标准全量评估模式，无需回滚代码。
- **审计保留**：关闭开关后，已有账本与报告中记录的 `static_signal`、`terminology_observations`、`cache_observation` 审计字段完好保留，供离线追溯与排查。
