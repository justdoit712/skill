# Skills 导航目录二开需求

文档日期：2026-09-20  
状态：需求整理，尚未实施

## 1. 项目目标

在现有技能商店基础上，建设一个每周自动更新的 Agent Skills 导航目录。定期从可信来源收集技能链接，通过中文简述和用途分类，让用户快速理解技能能做什么，并查看新增和更新情况。

**仅保存链接、介绍、分类和更新元数据，不下载完整技能包到本地，不安装或执行技能。**

为生成介绍、识别技能和判断变化，程序可以读取上游 README、SKILL.md 及必要的仓库元数据。“同步技能内容”在本需求中指根据这些资料更新索引信息，不代表镜像或下载技能包。

## 2. 当前项目基础与不足

根据当前本地代码检查：

- 已有技能链接索引、部分描述和分类，以及静态展示页面。
- `scripts/sync_skills.py` 定期读取上游 README，主要通过提取 GitHub 链接生成 `SKILL_SOURCES.json` 和 README 聚合列表。
- 现有聚合混合了技能仓库、技能合集和 DSH 插件等内容，条目数量不等于独立技能数量。
- 当前自动聚合流程没有充分保留上游描述、用途分类及具体技能路径。
- 现有每日同步配置需要调整为每周运行，展示数据与同步结果需要保持一致。

二开应复用现有采集和展示基础，重点改进来源管理、技能识别、介绍、分类和更新记录。

## 3. 范围边界

### 3.1 本期包含

1. 可配置的可信来源列表。
2. 每周定时采集，并支持手动触发。
3. 识别真实 Agent Skills，保留准确的上游链接。
4. 中文简要描述和用途分类。
5. 新增、更新、下架或不可用状态的记录与展示。
6. 可搜索、可按分类及来源筛选的技能目录。

### 3.2 本期不包含

- 下载、克隆或镜像完整技能包到本地。
- 自动安装、启用或执行任何技能及其脚本。
- 收录 DSH 插件、主题和其他不属于 Agent Skills 的扩展。
- 无限制抓取 GitHub 上的所有仓库。
- 搭建技能运行平台或对话助手。
- 声称所有收录技能都已实测、安全审计或获得质量认证。

二开包含必要的旧功能、旧数据和旧入口清理。具体删除范围见第 11 节，不能仅新增一套采集流程而保留不需要的旧流程继续运行。

## 4. 来源与收录规则

### 4.1 来源层级

| 来源类型 | 用途 | 要求 |
| --- | --- | --- |
| 团队官方仓库 | 主要收录来源 | 核实仓库归属后加入可信来源配置 |
| 可信社区聚合清单 | 补充发现渠道 | 从清单定位到原作者仓库，再确认具体技能 |
| 社区作者仓库 | 补充技能来源 | 经筛选加入来源配置，不因出现在任意 README 中就直接收录 |

Anthropic、Vercel、Cloudflare、Trail of Bits、Hugging Face、Google Labs、Stripe、Supabase、Expo、Sentry、Better Auth 等为待核实的初始来源候选。具体仓库地址、技能路径及归属以实施时核验结果为准，不沿用 README 中的历史数量作为当前事实。

GitHub 是托管平台；仓库位于 GitHub 不代表由 GitHub 官方发布。必须区分官方团队、社区作者和聚合清单。

### 4.2 收录对象

- 优先以具有 `SKILL.md` 的独立技能为条目。
- 一个仓库包含多个技能时，尽量逐个识别，链接到具体技能目录或说明文件。
- 模板、普通工具、插件容器和技能合集首页不应直接算作一个独立技能。
- 暂时无法展开的合集可以作为“技能合集”单独展示，数量与独立技能数量分开统计。
- 排除 DSH 来源及条目；即使其他清单引用了 DSH 插件，也不能因此自动纳入。

### 4.3 可信与质量表述

收录应有可追溯依据：来源归属明确、链接有效、技能用途可识别、有实际说明内容。官方来源是优先收录的依据，但不等同于每项技能都经过实际效果验证。

不以 Star 数作为唯一门槛，不把“成功抓到链接”直接标为“高质量”。信息不足或类型不明确的条目进入待确认状态，避免向用户展示编造的简介和分类。

## 5. 采集与信息同步

1. 从配置中的可信仓库和清单发现候选技能。
2. 优先读取上游结构化数据、技能元信息及已有分类，避免只提取 README 中的全部 GitHub 链接。
3. 必要时读取 README、SKILL.md，确认用途、实际路径及适用环境。
4. 对同一仓库、同一技能路径去重；记录多个发现来源，不重复生成技能条目。
5. 生成或更新中文简述及分类，保存索引。
6. 比较本次与上次结果，生成更新记录并更新展示页面。

只保存必要的索引、版本标识或内容摘要值；不将完整技能内容作为本地技能包保存。网页和索引的更新应使用同一份处理结果，避免出现多份数据长期不同步。

## 6. 条目展示信息

| 字段 | 要求 |
| --- | --- |
| 技能名称 | 保留上游名称，便于查找 |
| 原始链接 | 尽量直达具体技能目录或 SKILL.md |
| 中文简述 | 用一至两句话说明用途、主要输入或输出，避免空泛宣传 |
| 用途分类 | 一个主分类，可有多个补充标签 |
| 作者或团队 | 标明实际维护者 |
| 来源类型 | 官方、社区、技能合集等明确标识 |
| 收录依据 | 记录可信仓库或发现清单等来源信息 |
| 适用环境 | 仅记录上游明确声明的支持情况；未知则留空或标为未说明 |
| 时间与版本信息 | 首次发现时间、最近检查时间、可获得的上游变更标识 |
| 状态 | 正常、待确认、暂时无法访问、上游移除等 |

简介和分类必须有上游内容依据。不能仅凭仓库名称猜测功能，也不能把最近检查时间写成技能内容更新时间。

## 7. 分类要求

初始用途分类建议如下，实施时可根据实际条目合并或调整：

- 文档与办公：Word、PDF、PPT、表格等。
- 编程与代码质量：代码生成、重构、代码审查等。
- 前端与界面设计：React、网页设计、交互和样式等。
- 测试与安全：自动化测试、漏洞分析、审计等。
- 云服务与部署：云平台、部署、基础设施等。
- 数据与数据库：数据分析、数据库查询和优化等。
- AI 与机器学习：模型训练、评估、数据集和 Agent 开发等。
- 内容创作与营销：写作、图片、视频、传播和营销等。
- 自动化与工具集成：浏览器、外部服务、工作流等。
- 产品与项目协作：需求、项目管理、团队协作等。
- 其他／待分类：资料不足或尚无适合分类的条目。

优先继承可靠的上游分类，再映射到统一目录。必要时可用模型辅助生成中文简介和语义分类，保留依据及待确认状态；不要求用户逐条手工整理。

“用途分类”“来源可信度”“适用环境”应分开保存，不能混为一个标签体系。

## 8. 每周更新与变更展示

- 将相关技能采集任务改为每周运行一次；具体星期和时间由实施配置确定。
- 保留手动触发入口，方便调试或临时更新。
- 优先增量处理新增或发生变化的条目，避免重复读取和重复生成简介。
- 更新记录至少区分：新增技能、技能说明或内容变化、链接或分类修正、上游移除或不可用。
- 判断内容变化时，优先使用技能相关文件的版本或摘要；不能把仓库其他文件的提交直接当作该技能更新。
- 报告注明变化依据；仅检查成功或抓取时间改变，不算技能更新。
- 单个来源请求失败时，保留上次有效数据并记录失败；不得把临时网络问题当作批量下架。
- 上游确认移除的条目保留历史状态，避免静默消失。
- 每次运行给出新增数、更新数、状态变化数、失败来源及对应条目链接。

## 9. 用户浏览体验

用户应能够：

1. 按用途分类浏览，快速回答“我想做某件事，可以看哪些 Skills”。
2. 搜索名称、中文简介、作者和标签。
3. 按官方／社区来源筛选。
4. 查看最近一次每周更新及历史变更摘要。
5. 点击直达上游技能页面，自行阅读和决定是否安装。

展示示意，仅说明信息形式，不表示这些技能已在本次任务中同步或验证：

| 技能 | 中文简述 | 分类 | 来源 |
| --- | --- | --- | --- |
| docx | 创建、编辑和分析 Word 文档 | 文档与办公 | Anthropic |
| react-best-practices | 指导 React 项目的性能优化 | 前端与界面设计 | Vercel |
| property-based-testing | 指导基于属性的测试 | 测试与安全 | Trail of Bits |

## 10. 验收标准

- 活跃索引和展示页面不再混入 DSH 插件条目。
- 可追溯到可信来源；官方标签有对应的仓库归属依据。
- 已收录独立技能有具体链接、中文简述和用途分类；待确认条目明确标识。
- 同一技能被多个清单引用时只展示一次，并保留来源信息。
- 合集与独立技能分别统计，不夸大技能数量。
- 每周自动运行及手动运行均可完成索引更新。
- 新增和变化能在更新记录中看到；无变化的技能不会因检查时间改变而重复报更新。
- 上游请求失败不会清空已有有效索引。
- 页面支持搜索、分类筛选和来源筛选，数据与索引一致。
- 整个流程不下载完整技能包，不安装、启用或执行技能。
- 已删除 DSH 采集配置、现存 DSH 条目及展示入口，下一次同步不会重新引入。
- 不再运行与本需求无关的 ClawHub 软件包／CLI 信息同步任务。
- 被替代的旧同步入口、无调用代码和不再使用的依赖已清理；页面无失效入口。

## 11. 二开前后的清理与删除清单

### 11.1 先删除不需要的采集来源和展示内容

| 对象 | 具体处理 | 完成条件 |
| --- | --- | --- |
| `scripts/sync_skills.py` 中的 DSH 配置 | 删除 `UPSTREAM_SOURCES` 中的 `awesome_dsh_plugin`、对应 `SELF_REPOS` 配置和生成模板中的 DSH 来源链接 | 采集程序不再请求该来源，生成结果中不再出现 DSH 分组 |
| `SKILL_SOURCES.json` 中的旧 DSH 来源记录 | 从活跃索引移除旧 DSH 来源记录；其中确为 Agent Skill 的仓库，只有从允许来源重新发现并验证后才能重新纳入 | 不以 DSH 清单作为收录依据，不沿用旧的 4017 条统计 |
| README 社区聚合区 | 删除 Awesome DSH Plugin 来源说明、分组及条目，使用清理后的索引重新生成 | README 与新索引一致 |
| 其他索引、页面和生成文件中的 DSH 引用 | 搜索并清理实际存在的 DSH 插件卡片、导航、统计及数据；其他来源带入的 DSH 插件也应剔除 | 没有通过其他入口残留或重新带入的 DSH 插件 |
| `.github/workflows/sync_clawhub.yml` | 删除现有独立任务 | 不再每天自动写入 ClawHub 软件包与 CLI 信息 |
| `scripts/sync_clawhub.py` | 随对应任务删除 | 不再维护与具体技能导航无关的仓库软件包／CLI 同步脚本 |
| README 中自动生成的 ClawHub Packages／CLI 区块 | 删除对应生成内容，并检查是否有其他引用 | 导航聚焦技能条目，不展示仓库内部软件包作为技能 |

删除现有 ClawHub 同步功能的原因是该脚本采集 `openclaw/clawhub` 仓库的 `packages` 和 CLI 信息，并非识别具体的 Agent Skills；这不代表永久禁止未来通过合适方式接入可信的技能注册表。

### 11.2 新流程接通后，删除被替代的旧实现

- 替换 `scripts/sync_skills.py` 中“扫描全文 GitHub 链接即收录”的逻辑，删除不再使用的提取与生成分支。
- 调整 `.github/workflows/sync-skills.yml` 为每周运行；相关重复每日任务和旧入口应移除，不与新任务并行写入索引。
- 检查根目录 `main.py`、`crawler.py`、`scheduler.py`、`data_manager.py`、`api_client.py`、`api_server_example.py` 及批处理、计划任务脚本：可复用部分整合进新流程，被替代且无调用的部分删除。
- 对应清理无用途的依赖、配置项和启动说明。文件是否删除以实际调用关系为依据，不在新流程尚依赖它时提前删除。
- 统一 `data/` 与 `public/data/` 的数据来源。若部署需要生成副本，明确由程序生成；删除不再使用的旧数据文件，避免两套独立维护的索引。
- 清理页面中不再属于新目录的入口、旧宣传和失效链接；删除或改写 README 及相关说明中不准确的数量、“每日更新”“全部高质量”等表述。

### 11.3 现有本地技能包和附带项目的处理边界

用户明确不需要下载技能包，因此新导航不再依赖本地技能包、压缩包备份、安装入口或助手应用作为运行前提。

- 现有 `skills/` 中若有可用技能，可提取其上游链接纳入索引；不因已经存在于本地就自动认定为可信或优质。
- `projects/` 等附带应用及本地技能包不再作为新产品的主导航内容。
- 实施时盘点这些目录的文件、引用和作用，把确认不属于目标产品且无引用的内容列入具体删除清单再清理；不能只凭目录名整目录删除尚未检查的用户代码或资料。
- 历史提交留在 Git 历史中，不为清理 DSH 重写 Git 历史。需求文档中的说明不属于需要清除的运行时 DSH 内容。

### 11.4 清理验证

清理前后核对文件变更清单、索引条目数量和来源分布。运行一次新同步流程，确认 DSH 不会重新出现、有效技能仍可浏览、索引与页面一致、仅有预期的每周任务参与更新。

## 12. 建议实施顺序

1. 盘点旧任务和入口，删除第 11.1 节中不需要的来源、任务和展示内容。
2. 核实初始官方仓库，实现技能级链接识别、去重和稳定的数据结构。
3. 补齐中文简述、用途分类及来源依据。
4. 接入每周增量同步和变更报告，删除被替代的旧实现与无用依赖。
5. 更新导航页面和 README，统一统计口径，完成清理验证。
