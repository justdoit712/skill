# 阿里云百炼平台（DashScope）模型池剔除与适配说明

本文档详细说明在技能评估任务（`catalog assessment`）中，**需要从阿里云百炼模型轮换池中删除/排除的模型清单**及其**根本技术原因**。

本文档仅适用于 `config/models/bailian.json` 及通过该模板激活的 `config/models/model.json`。

---

## 一、剔除模型总览

截至当前版本，已从百炼池子中明确剔除 **11 个** 模型，分为四类致命缺陷：

| 模型名称 | 缺陷类别 | 运行时表现 / 报错信息 | 处置决定 |
| :--- | :--- | :--- | :--- |
| **`qvq-max`** | 权限/接口不支持 | `HTTP 400: current user api does not support http call` | **永久剔除**（引发熔断） |

| **`qwen-vl-max`** | 视觉长文本输出破损 | `Unterminated string starting at: line 26 column 18` | **剔除**（引文未闭合） |
| **`qwen-vl-plus`** | 视觉长文本输出破损 | 视觉模型对 Markdown 引文转义失效 | **剔除**（引文未闭合） |

## 二、各分类技术根因深度分析

### 1. 权限与接口不支持类（高危熔断级别）
- **涉及模型**：`qvq-max`, `qvq-plus`
- **问题现象**：
  ```text
  [停止] 请求配置错误 (HTTP 400)，已停止运行。
  [停止] 当前响应用量未知；本条状态已保存，后续付费调用已停止。
  HTTP 400：code=invalid_parameter_error; message=current user api does not support http call
  ```
- **技术根因**：
  百炼平台上的 `QVQ` 系列为专属实验模型，不支持常规 API Key 直接通过 OpenAI 兼容 HTTP 接口（`v1/chat/completions`）发起推理调用。
  该报错返回的不是预期的推理前无费拒绝（如 `max_tokens`），系统无法核实服务商是否产生在途计费，触发**资金安全最高级熔断机制**，导致整个批次任务被强制停止。

---

### 2. 视觉多模态系列（长引文输出截断破坏 JSON）
- **涉及模型**：
  - `qwen-vl-max`
  - `qwen-vl-plus`
  - `qwen3-vl-plus`
  - `qwen3-vl-plus-2025-09-23`
  - `qwen3-vl-235b-a22b-instruct`
  - `qwen3-vl-32b-instruct`
  - `qwen3-vl-8b-instruct`
  - `qwen3-vl-flash`
- **问题现象**：
  ```text
  模型输出校验未通过，排除该模型并切换：qwen-vl-max（模型输出不是合法 JSON：Unterminated string starting at: line 26 column 18）
  [格式异常] 初评输出格式不合法（OUTPUT_JSON_INVALID），已保存 blocked
  ```
- **技术根因**：
  1. **本职定位偏差**：视觉模型（VL）的核心优化点在图像图文理解，而非严格 Schema 的纯文本格式输出；
  2. **引文字符串未闭合**：评估要求在 `evidence_traceability.citations` 中输出原文事实引用（`quote`）。当原文存在长 Markdown、特殊代码段或换行时，视觉模型极易漏掉双引号转义，或在输出长引文的中途意外遇到终止符（`finish_reason: stop`），导致 JSON 字符串未闭合即截断；
  3. **延迟过高**：视觉模型处理纯文本评估的响应时间过长（单次 15~45 秒），严重拖慢整体吞吐率。

---

### 3. 小尺寸推理蒸馏类（空响应缺陷）
- **涉及模型**：`deepseek-r1-distill-qwen-7b`
- **问题现象**：
  ```text
  模型返回空正文，有限重试 1/2: deepseek-r1-distill-qwen-7b
  模型空响应达到尝试上限，本轮跳过并冷却 30 分钟：deepseek-r1-distill-qwen-7b
  ```
- **技术根因**：
  7B 级蒸馏小模型在开启 `response_format: json_object` 时，容易将思考过程（`<think>`）或系统指令与生成正文混淆，最终返回空字符串（`content=""`），触发系统重试上限并被迫冷却 30 分钟。

---

### 4. 代码专用模型（分类与结构约束无法收敛）
- **涉及模型**：`qwen3-coder-next`
- **问题现象**：
  ```text
  模型输出校验未通过，排除该模型并切换：qwen3-coder-next（main_category 缺失或不在允许的主分类内：None；允许 编程开发、文档办公、内容创作...）
  ```
- **技术根因**：
  代码生成微调模型（Coder）强于编写代码，但在文本理解、多维度质量把关与 10 大标准化业务主分类收敛上泛化能力不足，频繁输出 `None` 或非法自定义类别，无法满足 Schema 校验。

## 三、附录：关于 `max_tokens` 参数不兼容的说明

在百炼运行日志中，以下纯文本模型可能会出现批量跳过现象：
- `qwen-plus-0112`
- `qwen3-235b-a22b`
- `qwen-coder-plus`
- `qwen-turbo`
- `qwen-plus-2025-01-25`

- **提示信息**：`模型参数不兼容，跳过并选择下一个（max_tokens）`
- **是否需要删除？**：**不需要删除**。
  这是因为 `config/models/bailian.json` 中配置了 `"max_output_tokens": 20000`，而百炼的经典版 Qwen 模型在兼容模式下最大仅支持 1500~8192 Token。
  - **解决方案**：若希望激活这批模型，只需将 `limits.max_output_tokens` 降为 `8192` 或 `4096`，系统便会自动将其纳入正常轮换；
  - 若保持当前配置，系统已具备成熟的推理前参数拒绝拦截机制，会自动安全跳过，不会产生费用或中断任务。

## 四、百炼模型池推荐维护规范

1. **坚持纯文本/通用推理为主**：只保留百炼平台通用文本大模型（如 `qwen-max`、`glm-4.x`、`deepseek-v3.x` 等）。
2. **严禁引入任何视觉多模态模型**：严禁将带有 `-vl-`、`-vl`、`qvq` 的模型放入纯文本评估池。
3. **严禁引入小尺寸蒸馏模型**：7B 及以下模型不具备稳定输出复杂 JSON 证据链的能力。
4. **遇在途异常一键恢复命令**：
   ```powershell
   .\.venv\Scripts\python.exe tools/run_local.py --reset-recovery
   ```
